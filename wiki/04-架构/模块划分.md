# 模块划分

> 本章按数据库 schema 划分模块边界：public 承载核心业务与授权，对外暴露层为单 schema `api_v1_public`（sales/inventory 测试域已退役、占位目录已清理），extensions（net/cron 等）是扩展宿主。表/对象清单以 db/ 下实际 SQL 为准。

## schema 一览

| schema | 职责 | 目录 | 说明 |
| --- | --- | --- | --- |
| public | 核心业务：镜像表、自主表、授权、审计、日志、IP 归属；全部业务函数/触发器/视图/RLS | db/src/public/、db/migrations/public/ | 物理表 24 张（064 镜像 6 + 065 业务 18），另含 schema_migrations |
| api_v1_public | 对外 API 暴露层（现行）：视图投影（视图名 = 底层表名）+ RPC 包装函数 | db/api_v1/public/ | 只放投影与包装，不放物理表；29 视图 + 44 RPC 全部在此 |
| ~~api_v1_sales / api_v1_inventory~~ | ~~对外 API 暴露层声明~~ | 2026-08-15 退役；2026-08-19 从 postgrest.conf 移除、占位目录已清理；运行态只暴露 api_v1_public |
| net | pg_net 扩展宿主 schema | 扩展管理 | owner=postgres；已对 authenticated REVOKE EXECUTE（SSRF 防护，02-schemas） |
| cron | pg_cron 扩展宿主 schema | 扩展管理（Pigsty 集群级） | cron.job / cron.job_run_details |
| 扩展（非 schema） | **不存在 extensions schema**：pgcrypto/pgtap 装在 public，pg_net 宿主 net，pg_cron 宿主 cron；ip2region/GeoLite2 离线表在 public；说明文档见 wiki/01-项目简介/扩展/ | wiki/01-项目简介/扩展/、infra/pigsty.yml | 以 infra/pigsty.yml 为权威 |

> schema 现实（以 db/init/02-schemas.sql 为准）：public、api_v1_public、net（pg_net 宿主）——**不存在 extensions schema**，也不存在 api_v1_sales / api_v1_inventory schema（postgrest.conf 声明已于 2026-08-19 移除）。db/api_v1/ 下含 _shared（空，apply-src API 模块排序前缀 _shared 在前）、public（实际内容）。原兼容视图 public.sys_user / public.casbin_rule 已于 2026-08-20 移除（不再借鉴 Casbin 权限模型）。

## api_v1：对外暴露层

职责：视图投影（29 个视图文件）+ RPC 包装（44 个函数文件，数量随演进变化）。函数命名注意：文件名统一 `rpc_xxx.sql`，但函数名部分带 `rpc_` 前缀（如 rpc_create_department、rpc_set_role_data_scope）、部分不带（如 search_users、update_config、get_user_menu、webhook_logto）——HTTP 端点是 `/rpc/<函数名>`。

### 视图分类

| 类别 | 视图 | 说明 |
| --- | --- | --- |
| 基础投影 | users、role、department、position、iam_menu、iam_role_menu、user_tenants、dict_type、dict_data、login_log、audit_log、app_config、config_admin、cron_job_log、organization_role、user_position | 视图名 = 底层表名；隐藏敏感列（如 users 不含 password_hash） |
| 列表/详情聚合 | v_user_list、v_role_list、v_dept_list、v_dict_list、v_user_roles、v_role_users、v_user_role_detail、v_role_menu_detail、v_audit_log_detail | join 租户名/部门名/绑定计数等 |
| 时间线/统计 | v_audit_log_timeline、v_system_stats、v_system_stats_realtime | 按天聚合、系统统计卡片 |
| 地理增强 | v_login_log | LATERAL geo_locate 实时地理 join |

### RPC 分类

| 类别 | 代表函数 | 权限模型 |
| --- | --- | --- |
| 查询类（INVOKER + RLS） | search_users、search_audit_log、get_dept_tree、get_audit_log_timeline、get_all_public_configs | 无额外门槛，RLS 行级兜底 |
| 自查/工具 | get_current_user、get_user_menu、get_user_profile、get_config、ensure_user | DEFINER，仅返回自身/镜像数据 |
| CRUD（DEFINER + 权限点） | rpc_create/update/delete_department、rpc_create/update/delete_menu、rpc_create/update/delete_dict_*、rpc_create/update/delete_position、rpc_assign_user_positions、rpc_update_user_profile、rpc_update_config、rpc_import_csv | require_permission / has_permission（public:* 权限点） |
| 授权绑定 | rpc_set_role_menus、rpc_set_role_data_scope、rpc_get_role_data_scope、rpc_get_role_permissions、rpc_get_user_roles | has_permission（public:role-menu:bind / public:data-scope:bind / public:tenant-member:list） |
| 平台级（超管） | rpc_list_cron_jobs、rpc_list_cron_job_runs、rpc_list_webhook_events、rpc_replay_webhook_event | require_super_admin / is_super_admin |
| 组织/租户 | rpc_list_tenants、rpc_list_tenant_members | has_permission（public:tenant:list / public:tenant-member:list） |
| webhook 入口 | webhook_logto | GRANT EXECUTE TO web_anon（幂等分发） |
| 登录日志 | rpc_search_login_logs | has_permission('public:login-log:list') + 租户成员过滤 |

- **权威扩展清单**：infra/pigsty.yml（唯一 inventory，2026-08-19 方案 A；pg_extensions 节点级装包 + pg_databases[].extensions 库内启用；db/init/01-extensions.sql 已于 2026-08-19 移除），逐扩展说明见 wiki/01-项目简介/扩展/：

- **辅助数据**：`ip_region_v4`（ip2region 离线库，import-ip2region.sh 导入）、`ip_geolite2_*`（GeoLite2-City staging + 终表，import-geolite2.sh 导入）；扩展说明文档见 wiki/01-项目简介/扩展/（加密辅助.md / pgTAP单元测试.md / 异步HTTP.md 等）。

## 模块间依赖与数据流约束

1. **建表依赖**：064 镜像表先建（users/tenants/role 等），065 业务表 FK 指向镜像表（user_profile→users/tenants/department、user_role→users/role 等）；dbmate 按文件名排序应用。
2. **写通道约束**：
   - 镜像表（users/tenants/role/organization_role/user_tenants/user_role）**业务只读**，写通道仅 sync_* / ensure_user / 对账脚本（N4：镜像只读原则）；
   - 自主表（iam_*、department、dict_*、app_config 等）管理端经 RPC 写，RPC 内 has_permission 门槛；
   - audit_log/login_log/webhook_event_log 写经 SECURITY DEFINER 函数或同步函数，不直接暴露 INSERT（role_admin 无 DELETE 授权）。
3. **apply-src 重放顺序**（scripts/apply-src.sh）：bootstrap（init 扩展/schema + src types 枚举）→ src/public（types → 其余，多遍收敛）→ api_v1（API_MODULES="_shared public"：rpc → views → privileges/zz_grant_all.sql 最后）→ init → migrations；后置模块可依赖前置模块，反之不可。
4. **跨 schema 依赖**：api_v1_public 只依赖 public（视图投影 public 表、RPC 调用 public 函数）；api_v1_public 不写 public 表（除 SECURITY DEFINER 内部）。
5. **权限面**：db/api_v1/public/privileges/zz_grant_all.sql 按角色分层（authenticated SELECT、role_guest/role_editor/role_admin 递增、super_admin ALL）；RLS 是数据级最终边界；角色（PG 系统角色）由 Pigsty 管理（02-schemas 头注参考）。
6. **退役对象与新旧并存**：iam_api / iam_role_api 已删（055 单表化）；inventory/sales 测试模块已退役（063），postgrest.conf 声明与占位目录已于 2026-08-19 清理、init-apisix-routes.sh 已移除对应路由（按需重建）；net.request_status 等旧遗留已清理——模块归属以当前 db/ 为准，暴露层以「api_v1_public 单 schema（compose 运行态权威）」为准。
