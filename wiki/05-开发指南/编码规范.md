# 编码规范

> 定位：SQL 与脚本的命名、注释、审计字段等约定。本页事实均以 `db/` 下当前代码为准（无 `sys_` 表前缀；Casdoor/casbin 时代命名已过时，不适用）。

## 命名规范

### 表

- 业务表/镜像表**无 `sys_` 前缀**：`users`、`tenants`、`role`、`organization_role`、`user_tenants`、`user_role`（Logto 镜像表）；`department`、`position`、`user_profile`、`user_position`、`iam_menu`、`iam_role_menu`、`iam_role_data_scope`、`dict_type`、`dict_data`、`app_config`、`audit_log`、`login_log`、`cron_job_log`、`webhook_event_log`、`ip_geolite2_*`、`ip_region_v4`（业务/自主表）。
- `iam_*` 前缀保留给权限域表（iam_menu / iam_role_menu / iam_role_data_scope）。
- `public.sys_user` / `public.casbin_rule` 兼容视图已于 2026-08-20 **移除**（不再借鉴 Casbin 权限模型）：用户数据直接查 `public.users`（Logto 镜像）+ `public.user_profile`（业务档案），授权以 `iam_role_menu → iam_menu` 为准。历史 `sys_*` 表（sys_role/sys_api/sys_menu/sys_user_session 等）已全部移除（见 `db/tests/public/01_schema_test.sql` 的 `hasnt_table` 断言）。

### 视图

| 位置 | 命名 | 示例 |
| --- | --- | --- |
| `db/api_v1/<域>/views/`（对外暴露） | 视图名 = 底层表名，或 `v_*` 列表/明细视图；目录按域组织（`_shared`/`public`，当前活跃模块 public）；运行态仅暴露 `api_v1_public`（compose 权威） | `users`、`role`、`iam_menu`、`v_user_list`、`v_role_list`、`v_dept_list`、`v_audit_log_timeline` |
| `db/src/public/views/`（内部兼容投影，已清空） | 2026-08-20 移除 `sys_user`/`casbin_rule` | — |

### RPC（api_v1_public 函数）

- **CRUD 类统一 `rpc_` 前缀**：`rpc_create_menu`、`rpc_update_department`、`rpc_delete_dict_data`、`rpc_set_role_menus`、`rpc_get_position_tree` 等（`db/api_v1/public/rpc/` 共 44 个文件）。Schema 布局 = `public`/`api_v1_public`/`net`（pg_net 宿主）；运行态仅暴露 `api_v1_public`（compose 权威），目录按域组织（`db/api_v1/{_shared,public}/`），当前内容全部在 public 子目录。
- 历史函数保留原名（不强制改名）：`get_user_menu`、`get_role_permissions`、`get_current_user`、`search_users`、`search_audit_log`、`update_config`、`webhook_logto`、`ensure_user`、`import_csv`。
- 参数用 `p_` 前缀 + 蛇形（`p_role_code`、`p_menu_ids`）；**枚举不进函数签名**（参数用 `text`，函数体内显式 cast，JSON 友好）。

### 底层函数（public schema，无前缀）

`db/src/public/functions/`（37 个文件）一文件一函数：`current_user_id`、`current_tenant_id`、`current_user_roles`、`is_super_admin`、`has_permission`、`require_permission`、`require_super_admin`、`update_updated_at`、`audit_trigger_func`、`write_audit_log`、`log_operate`、`sync_user_upsert` 等。

### 触发器

- `updated_at` 自动维护：`trg_<表>_updated_at`（BEFORE UPDATE，统一由 `db/src/public/triggers/trg_updated_at.sql` 的 DO 块为所有含 `updated_at` 的 BASE TABLE 批量创建）。
- 数据变更审计：`trg_audit_<表>`（AFTER INSERT/UPDATE/DELETE，执行 `audit_trigger_func`）。当前 9 个：`trg_audit_app_config`、`trg_audit_department`、`trg_audit_dict_data`、`trg_audit_dict_type`、`trg_audit_iam_menu`、`trg_audit_position`、`trg_audit_role_menu`、`trg_audit_user_position`、`trg_audit_user_profile`。
- **镜像表（users/tenants/role/user_tenants/user_role/organization_role）不挂审计触发器**：写入源是 Logto webhook，事件本身可追溯，避免高频 upsert 审计爆炸。

### 索引

命名 `idx_<表>_<列>`（基线 065 实测）：`idx_audit_created`、`idx_iam_menu_api_code`、`idx_iam_menu_api_url_method`（部分唯一：`WHERE api_url IS NOT NULL`）、`idx_iam_role_menu_role`、`idx_login_log_user`、`idx_user_profile_tenant` 等。

### 约束与枚举

- 约束名：基线中 NOT NULL 类沿用 `sys_<表>_<列>_not_null`（历史遗留），新迁移建议用表语义前缀（`iam_menu_button_nav_null_check`、`iam_menu_api_pair_check` 等 CHECK 先例）；主键/外键/唯一用 `*_pkey` / `*_fkey` / `*_key`。
- 枚举：统一归 `db/src/public/types/`（当前 5 个文件：`audit_operation`、`gender`、`menu_type`（iam_menu_type）、`request_status`、`scope_type`；其中 `request_status` 已在 18 号文档登记退役——全库零引用）。值只增不删、不重排；废弃值用 `z_deprecated_*` 前缀 RENAME VALUE。

## 审计字段约定

模板权威文件：`db/src/public/templates/audit_fields.sql`（10 个 ABP 风格接口模板，含决策树与触发器绑定示例）。当前库内实际应用情况：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `created_at` | `timestamptz NOT NULL DEFAULT now()` | 创建时间（数据库默认值填充，应用层不应修改） |
| `updated_at` | `timestamptz NOT NULL DEFAULT now()` | 最后修改时间，由 `update_updated_at()` 触发器自动维护 |
| `created_by` / `updated_by` / `deleted_by` | `text`（Logto 用户 id）为主流；`department`/`audit_log` 历史为 `uuid` | 不强制外键（避免循环引用）；审计模板仍写 UUID，35 号审查建议整体改 TEXT（待裁决） |
| `deleted_at` | `timestamptz` | 软删除标记（NULL=未删，非 NULL=删除时间），等效 ABP IsDeleted + DeletionTime |
| `logto_updated_at` | `timestamptz` | 镜像表专用：Logto 权威 updatedAt（乱序守护比较基准）；视图层映射为 `updated_at` 输出 |

### 模板速选

| 场景 | 模板 | 字段 |
| --- | --- | --- |
| 关联表（user_role/iam_role_menu/user_tenants/user_position） | 模板 1 | `created_at` |
| 配置/字典表（app_config/dict_type/dict_data） | 模板 4/6 | `created_at, updated_at`（+可选 `_by`） |
| 核心业务表（department/position/user_profile） | 模板 10 | `created_at, created_by, updated_at, updated_by, deleted_at, deleted_by` |
| 审计/日志表（audit_log/login_log/webhook_event_log） | 无 | 自身即审计；append-only（写走 SECURITY DEFINER） |
| 镜像表（users/tenants/role/...） | 模板 4 + 同步元数据 | `created_at` + `logto_updated_at`（无 `_by` 语义） |

### 审计写入链路

1. **数据变更**：`trg_audit_*` → `audit_trigger_func()` → `write_audit_log()` → `audit_log`（`log_type='data_change'`, `source='trigger'`）。
2. **业务操作**：RPC 内 `PERFORM log_operate(module, action, target_type, target_id, result, detail)` → `audit_log`（`log_type='operate'`）。
3. 辅助函数 `audit_created_at()` / `audit_user_fields()` / `audit_deletion_user()` 存在但**当前无表绑定**（35 号审查 D2 登记：现库生产审计链为 `audit_trigger_func` + `write_audit_log`；如需绑定请先裁决 `_by` 类型）。

## updated_at 触发器统一管理

`db/src/public/triggers/trg_updated_at.sql` 一个 DO 块统一管理：遍历 public schema 中含 `updated_at` 列的 BASE TABLE，按 `pg_trigger` 守卫幂等创建 `trg_<表>_updated_at`（视图列已被 BASE TABLE 过滤排除）。底层函数 `update_updated_at()` 在 `db/src/public/functions/update_updated_at.sql`。

```sql
-- 新表如需自动维护 updated_at，无需手写触发器——建表含 updated_at 列后重放 src 即自动覆盖
CREATE TABLE public.xxx (
    ...
    updated_at timestamptz NOT NULL DEFAULT now()
);
```

## 注释规范

1. **SQL 文件头注释**（一文件一对象）：

```sql
-- db/src/public/functions/<name>.sql
-- FUNCTION: public.<name>（17 号文档归位：迁移 <xxx> 删定义段，本文件为唯一权威）
-- 回放终态: <迁移名>；幂等写法（§9 模板）
```

2. **函数头注释**：语义、权限码、演进历史（如 `has_permission.sql` 标注 055 单通道收敛）。
3. **COMMENT ON 随定义走**：函数/视图/触发器/类型均带 `COMMENT ON`；迁移内 `COMMENT ON FUNCTION/VIEW/TRIGGER/TYPE` 属违规残留（17 号铁律 §5）。
4. **迁移文件头注释**：用途、涉及表、幂等说明、`-- migrate:up` / `-- migrate:down` 标记（标记前只允许注释）。
5. **枚举文件头**：语义、使用位置（`<表>.<列>`）、演进史、废弃值策略（见 `db/src/public/types/scope_type.sql` 样板）。

## 幂等写法模板（src/api_v1 源文件强制）

| 对象 | 常规变更 | 结构变更（签名/列集变化） |
| --- | --- | --- |
| 函数 | `CREATE OR REPLACE FUNCTION` | 同文件 `DROP FUNCTION IF EXISTS` + 重建；**禁止重载（一名一签名）** |
| 触发器函数 | `CREATE OR REPLACE FUNCTION` | 函数文件 DROP+重建、触发器文件 `DROP TRIGGER IF EXISTS`+重建，两文件同一提交 |
| 视图 | `CREATE OR REPLACE VIEW`（仅末尾加列） | 删列/改名 → 同文件 `DROP VIEW IF EXISTS` + `CREATE VIEW` |
| 触发器 | `DROP TRIGGER IF EXISTS` + `CREATE TRIGGER` | 同上 |
| RLS 策略 | — | `DROP POLICY IF EXISTS` + `CREATE POLICY` |
| 枚举 | DO 块守卫 + `IF NOT EXISTS` | 值只增不删（§8.3 模板） |

**全对象禁令**：禁止 CASCADE（除迁移结构清理）；禁止源文件内显式 BEGIN/COMMIT；禁止 GRANT 散落（归 `zz_grant_all.sql`）；禁止一文件多对象。

## 脚本规范（scripts/）

| 要求 | 说明 |
| --- | --- |
| 幂等 | 重复执行结果一致（apply-src 全量重放、deploy-db 四步链均幂等） |
| 退出码 | `set -euo pipefail`；失败必须非 0 退出（apply-src 扫描命中即 exit 1） |
| 凭据 | 不硬编码密码，从 `.env.<env>` / `gateway/.env` 加载（如 `deploy-db.sh`） |
| 行尾 | 保持 LF（CRLF 脚本在 WSL 直接跑会 `$'\r': command not found`，18 号文档经验） |
| 日志 | 中文步骤编号输出（`[1/4]` 风格），失败列出具体文件/项 |
| 环境自适应 | 验证类脚本用 `to_regprocedure/to_regclass` 等守卫，dbmate 阶段跳过、apply-src 阶段生效 |
