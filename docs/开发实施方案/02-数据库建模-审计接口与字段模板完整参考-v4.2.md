## 0. 审计字段相关函数总览

| # | 函数名 | 触发时机 | 功能 | 必需性 |
|:---:|:---|:---|:---|:---|
| 1 | `update_updated_at()` | BEFORE UPDATE | 自动设置 `updated_at = now()` | ⭐ 必需（有 updated_at 的表） |
| 2 | `audit_user_fields()` | BEFORE INSERT/UPDATE | 自动填充 `created_by` / `updated_by` | 可选（推荐） |
| 3 | `audit_deletion_user()` | BEFORE UPDATE | 软删除时自动填充 `deleted_by` | 可选（推荐） |
| 4 | `audit_created_at()` | BEFORE INSERT/UPDATE | 强制保护 `created_at` 不可篡改 | 可选（推荐） |

### 0.1 函数详细说明

#### 函数 1：`update_updated_at()`

```sql
CREATE OR REPLACE FUNCTION update_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = now();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

| 项目 | 说明 |
|:---|:---|
| **触发时机** | BEFORE UPDATE |
| **功能** | 每次 UPDATE 时自动将 `updated_at` 设为当前时间 |
| **必需性** | 所有包含 `updated_at` 字段的表必须绑定 |
| **绑定示例** | `CREATE TRIGGER trg_user_updated_at BEFORE UPDATE ON sys_user FOR EACH ROW EXECUTE FUNCTION update_updated_at();` |
| **注意** | 应用层不应手动设置 `updated_at`，由触发器统一维护 |

---

#### 函数 2：`audit_user_fields()`

```sql
CREATE OR REPLACE FUNCTION audit_user_fields()
RETURNS TRIGGER AS $$
BEGIN
    IF (TG_OP = 'INSERT') THEN
        NEW.created_by := NULLIF(current_user_id(), '00000000-0000-0000-0000-000000000000'::uuid);
    ELSIF (TG_OP = 'UPDATE') THEN
        NEW.updated_by := NULLIF(current_user_id(), '00000000-0000-0000-0000-000000000000'::uuid);
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

| 项目 | 说明 |
|:---|:---|
| **触发时机** | BEFORE INSERT / UPDATE |
| **功能** | INSERT 时自动填充 `created_by`，UPDATE 时自动填充 `updated_by` |
| **必需性** | 可选（推荐，避免应用层遗漏） |
| **NULL 处理** | 无 JWT 上下文时（全零 UUID），自动转为 NULL |
| **NULL vs 全零 UUID** | NULL 语义更清晰（未知/无用户），查询更方便（`IS NULL`），聚合更准确（COUNT 自动忽略 NULL） |
| **绑定示例** | `CREATE TRIGGER trg_user_audit_user BEFORE INSERT OR UPDATE ON sys_user FOR EACH ROW EXECUTE FUNCTION audit_user_fields();` |

---

#### 函数 3：`audit_deletion_user()`

```sql
CREATE OR REPLACE FUNCTION audit_deletion_user()
RETURNS TRIGGER AS $$
BEGIN
    IF (OLD.deleted_at IS NULL AND NEW.deleted_at IS NOT NULL) THEN
        NEW.deleted_by := NULLIF(current_user_id(), '00000000-0000-0000-0000-000000000000'::uuid);
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

| 项目 | 说明 |
|:---|:---|
| **触发时机** | BEFORE UPDATE |
| **功能** | 仅当 `deleted_at` 从 NULL 变为非 NULL 时，自动填充 `deleted_by` |
| **必需性** | 可选（推荐，追踪谁执行了软删除） |
| **不触发场景** | 恢复软删除（NOT NULL → NULL）时不触发，需手动清除 `deleted_by` |
| **绑定示例** | `CREATE TRIGGER trg_user_audit_deletion BEFORE UPDATE ON sys_user FOR EACH ROW EXECUTE FUNCTION audit_deletion_user();` |

---

#### 函数 4：`audit_created_at()`

```sql
CREATE OR REPLACE FUNCTION audit_created_at()
RETURNS TRIGGER AS $$
BEGIN
    IF (TG_OP = 'INSERT') THEN
        NEW.created_at := now();
    ELSIF (TG_OP = 'UPDATE') THEN
        NEW.created_at := OLD.created_at;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

| 项目 | 说明 |
|:---|:---|
| **触发时机** | BEFORE INSERT / UPDATE |
| **功能** | INSERT 时强制覆盖为 `now()`，UPDATE 时强制恢复为旧值 |
| **必需性** | 可选（推荐，作为最后一道防线） |
| **防护目标** | 防止应用层恶意或错误修改 `created_at` |
| **绑定示例** | `CREATE TRIGGER trg_user_audit_created_at BEFORE INSERT OR UPDATE ON sys_user FOR EACH ROW EXECUTE FUNCTION audit_created_at();` |

## 1. 模板选择决策树

```
新建数据库对象需要审计字段吗？
│
├── 系统级表（sys_secret / sys_token_blacklist / sys_cron_log）
│   └── ❌ 不需要审计字段
│       原因：系统级表无用户上下文，审计无意义
│
├── 审计日志表（sys_audit_log）
│   └── ❌ 不需要审计字段
│       原因：审计日志本身记录变更，无需再审计
│
├── 配置/字典表（sys_config / sys_dict_data 等）
│   └── ⚠️ 可选：模板 1（IHasCreationTime）或 模板 6（IAuditedObject）
│       原因：低频变更，但可能需要追踪谁修改了配置
│
├── 关联表（M:N 关系表，如 sys_user_role / sys_role_api）
│   └── ⚠️ 推荐：模板 1（IHasCreationTime）
│       原因：关联表通常只需知道"何时创建"，无需修改/删除审计
│
├── 日志/会话表（sys_login_log / sys_user_session）
│   └── ⚠️ 推荐：模板 1（IHasCreationTime）
│       原因：只追加、不修改，无需软删除
│
├── 视图（VIEW）
│   └── ❌ 不需要审计字段
│       原因：视图是虚拟表，审计字段应在基表中
│
├── 核心业务表（sys_user / sys_role / sys_department 等）
│   └── ✅ 推荐：模板 10（IFullAuditedObject）⭐⭐
│       原因：完整生命周期追踪（创建+修改+删除）
│
└── 只读/缓存表（如物化视图、缓存表）
    └── ❌ 不需要审计字段
        原因：数据从其他表同步，审计应在源表
```

### 接口 7：`ISoftDelete`

**性质：** `IsDeleted`（BOOLEAN，true/false）
**PostgreSQL 字段：** `deleted_at`（TIMESTAMPTZ 等价替代）

### 接口 10：`IFullAuditedObject` ⭐⭐

**性质：** `CreationTime`, `CreatorId`, `LastModificationTime`, `LastModifierId`, `IsDeleted`, `DeletionTime`, `DeleterId`（继承 6 + 9）
**PostgreSQL 字段：** `created_at`, `created_by`, `updated_at`, `updated_by`, `deleted_at`, `deleted_by`

```sql
    -- ============================================================
    -- 【模板 10】接口 IFullAuditedObject（推荐：完整审计）
    -- 性质：CreationTime, CreatorId, LastModificationTime, LastModifierId,
    --        IsDeleted, DeletionTime, DeleterId
    -- PostgreSQL 实现：6 个字段（deleted_at 取代表示 IsDeleted + DeletionTime）

    -- ============================================================

    -- 审计字段：完整审计（创建 + 修改 + 软删除）
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    created_by UUID,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by UUID,
    deleted_at TIMESTAMPTZ,
    deleted_by UUID,
    -- 注释：created_at = 创建时间，不可变
    -- 注释：created_by = 创建者（NULL=系统创建）
    -- 注释：updated_at = 最后修改时间（触发器自动维护）
    -- 注释：updated_by = 最后修改者（应用层/触发器填充）
    -- 注释：deleted_at = 软删除时间（NULL=未删除）
    -- 注释：deleted_by = 删除者（应用层/触发器填充）
```

## 5. 触发器绑定（配合审计字段）

### 5.1 `updated_at` 自动维护（必需）

```sql
-- 每个使用 updated_at 的表都需要绑定此触发器
-- 函数 update_updated_at() 已在 Migration 001 中定义

CREATE TRIGGER trg_<表名>_updated_at
    BEFORE UPDATE ON <表名>
    FOR EACH ROW EXECUTE FUNCTION update_updated_at();
```

### 5.2 `created_by` / `updated_by` 自动填充（可选，推荐）

```sql
-- 可选：通过触发器自动维护 created_by / updated_by
-- 注意：需要从 JWT claims 中获取当前用户 ID（current_user_id() 函数已定义）
-- 注意：无 JWT 上下文时（如系统任务），自动设为 NULL

CREATE TRIGGER trg_<表名>_audit_user
    BEFORE INSERT OR UPDATE ON <表名>
    FOR EACH ROW EXECUTE FUNCTION audit_user_fields();
```

### 5.3 `deleted_by` 自动填充（可选，推荐）

```sql
-- 可选：通过触发器自动维护 deleted_by
-- 注意：仅在 deleted_at 从 NULL 变为非 NULL 时触发

CREATE TRIGGER trg_<表名>_audit_deletion
    BEFORE UPDATE ON <表名>
    FOR EACH ROW EXECUTE FUNCTION audit_deletion_user();
```

### 5.4 `created_at` 强制保护（可选，推荐）

```sql
-- 可选：通过触发器强制保护 created_at
-- INSERT 时强制覆盖为 now()，UPDATE 时强制恢复为旧值

CREATE TRIGGER trg_<表名>_audit_created_at
    BEFORE INSERT OR UPDATE ON <表名>
    FOR EACH ROW EXECUTE FUNCTION audit_created_at();
```

### 8.1 示例：创建 `sys_article` 表（文章管理，使用模板 10）

```sql
CREATE TABLE sys_article (
    -- 主键
    id UUID PRIMARY KEY DEFAULT uuidv7(),
    
    -- 业务字段
    title VARCHAR(200) NOT NULL,
    content TEXT,
    author_name VARCHAR(50),
    status VARCHAR(20) NOT NULL DEFAULT 'draft' CHECK (status IN ('draft', 'published', 'archived')),
    tenant_id UUID NOT NULL REFERENCES sys_tenant(id) ON DELETE RESTRICT,
    
    -- 审计字段：模板 10（IFullAuditedObject）
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    created_by UUID,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by UUID,
    deleted_at TIMESTAMPTZ,
    deleted_by UUID
);

-- 索引（PostgreSQL 标准写法）
CREATE INDEX idx_article_tenant ON sys_article(tenant_id);
CREATE INDEX idx_article_status ON sys_article(status);

-- 绑定触发器
CREATE TRIGGER trg_article_updated_at
    BEFORE UPDATE ON sys_article
    FOR EACH ROW EXECUTE FUNCTION update_updated_at();

CREATE TRIGGER trg_article_audit_user
    BEFORE INSERT OR UPDATE ON sys_article
    FOR EACH ROW EXECUTE FUNCTION audit_user_fields();

CREATE TRIGGER trg_article_audit_deletion
    BEFORE UPDATE ON sys_article
    FOR EACH ROW EXECUTE FUNCTION audit_deletion_user();

-- 启用 RLS
ALTER TABLE sys_article ENABLE ROW LEVEL SECURITY;

CREATE POLICY article_tenant_isolation ON sys_article
AS RESTRICTIVE
USING (tenant_id = current_tenant_id())
WITH CHECK (tenant_id = current_tenant_id());

-- 注释
COMMENT ON TABLE sys_article IS '文章管理表';
COMMENT ON COLUMN sys_article.deleted_at IS '软删除时间，NULL=未删除';
```

### 8.2 示例：创建 `sys_login_log` 表（登录日志，使用模板 1）

```sql
CREATE TABLE sys_login_log (
    -- 主键
    id BIGSERIAL PRIMARY KEY,
    
    -- 业务字段
    user_id UUID REFERENCES sys_user(id) ON DELETE SET NULL,
    login_time TIMESTAMPTZ NOT NULL DEFAULT now(),
    ip_address VARCHAR(45),
    user_agent TEXT,
    login_result VARCHAR(20) NOT NULL CHECK (login_result IN ('success', 'failed', 'locked')),
    fail_reason VARCHAR(255),
    
    -- 审计字段：模板 1（IHasCreationTime）
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
    -- 注释：日志表只需记录创建时间，无需修改和软删除
);

-- 日志表不需要 updated_at 触发器
-- 日志表不需要 RLS（或仅允许 SELECT）
```

## 9. 总结

| 要点 | 说明 |
|:---|:---|
| **模板用途** | 不建表，仅作为字段参考片段 |
| **推荐模板** | 模板 10（IFullAuditedObject）—— 完整审计 |
| **核心字段** | `created_at`, `updated_at`, `deleted_at` + 可选 `_by` 字段 |
| **触发器** | `updated_at` 必须绑定 `update_updated_at()`；`_by` 字段推荐绑定 `audit_user_fields()` / `audit_deletion_user()` |
| **查询规范** | 所有业务查询必须加 `WHERE deleted_at IS NULL` |
| **外键策略** | `_by` 字段不强制外键约束，避免循环引用 |
| **NULL 语义** | `_by` 字段为 NULL 表示系统/匿名操作，优于全零 UUID |
| **ISoftDelete 实现** | `deleted_at IS NOT NULL` 等价 `IsDeleted = true` |
| **IDataFilter 实现** | 通过 RLS 策略 + 手动过滤实现运行时软删除过滤 |
