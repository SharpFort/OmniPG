## 0. 审计字段相关函数总览

| # | 函数名 | 触发时机 | 功能 | 必需性 |
|:---:|:---|:---|:---|:---:|
| 1 | `update_updated_at()` | BEFORE UPDATE | 自动设置 `updated_at = now()` | ⭐ 必需（有 updated_at 的表） |
| 2 | `audit_user_fields()` | BEFORE INSERT/UPDATE | 自动填充 `created_by` / `updated_by` | 可选（推荐） |
| 3 | `audit_deletion_user()` | BEFORE UPDATE | 软删除时自动填充 `deleted_by` | 可选（推荐） |
| 4 | `audit_created_at()` | BEFORE INSERT/UPDATE | 强制保护 `created_at` 不可篡改 | 可选（推荐） |
| 5 | `is_uuid_v7()` | - | 验证 UUID 是否为 v7 版本 | 可选（按需启用） |

### 0.1 函数详细说明

#### 函数 1：`update_updated_at()`

```sql
CREATE OR REPLACE FUNCTION update_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = now();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

| 项目 | 说明 |
|:---|:---|
| **触发时机** | BEFORE UPDATE |
| **功能** | 每次 UPDATE 时自动将 `updated_at` 设为当前时间 |
| **必需性** | 所有包含 `updated_at` 字段的表必须绑定 |
| **绑定示例** | `CREATE TRIGGER trg_department_updated_at BEFORE UPDATE ON department FOR EACH ROW EXECUTE FUNCTION update_updated_at();` |
| **注意** | 应用层不应手动设置 `updated_at`，由触发器统一维护 |

---

#### 函数 2：`audit_user_fields()`

```sql
CREATE OR REPLACE FUNCTION audit_user_fields()
RETURNS TRIGGER AS $$
BEGIN
    IF (TG_OP = 'INSERT') THEN
        NEW.created_by := current_user_id();  -- 无 JWT 上下文时返回 NULL
    ELSIF (TG_OP = 'UPDATE') THEN
        NEW.updated_by := current_user_id();
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

| 项目 | 说明 |
|:---|:---|
| **触发时机** | BEFORE INSERT / UPDATE |
| **功能** | INSERT 时自动填充 `created_by`，UPDATE 时自动填充 `updated_by` |
| **必需性** | 可选（推荐，避免应用层遗漏） |
| **NULL 处理** | 无 JWT 上下文时 `current_user_id()` 返回 NULL，`_by` 自动置 NULL |
| **NULL 语义** | `_by` 为 NULL = 系统/同步/匿名操作；查询用 `IS NULL`，聚合 COUNT 自动忽略 NULL |
| **绑定示例** | `CREATE TRIGGER trg_department_audit_user BEFORE INSERT OR UPDATE ON department FOR EACH ROW EXECUTE FUNCTION audit_user_fields();` |

---

#### 函数 3：`audit_deletion_user()`

```sql
CREATE OR REPLACE FUNCTION audit_deletion_user()
RETURNS TRIGGER AS $$
BEGIN
    IF (OLD.deleted_at IS NULL AND NEW.deleted_at IS NOT NULL) THEN
        NEW.deleted_by := current_user_id();  -- 无 JWT 上下文时返回 NULL
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

| 项目 | 说明 |
|:---|:---|
| **触发时机** | BEFORE UPDATE |
| **功能** | 仅当 `deleted_at` 从 NULL 变为非 NULL 时，自动填充 `deleted_by` |
| **必需性** | 可选（推荐，追踪谁执行了软删除） |
| **不触发场景** | 恢复软删除（NOT NULL → NULL）时不触发，需手动清除 `deleted_by` |
| **绑定示例** | `CREATE TRIGGER trg_department_audit_deletion BEFORE UPDATE ON department FOR EACH ROW EXECUTE FUNCTION audit_deletion_user();` |

---

#### 函数 4：`audit_created_at()`

```sql
CREATE OR REPLACE FUNCTION audit_created_at()
RETURNS TRIGGER AS $$
BEGIN
    IF (TG_OP = 'INSERT') THEN
        NEW.created_at := now();
    ELSIF (TG_OP = 'UPDATE') THEN
        NEW.created_at := OLD.created_at;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

| 项目 | 说明 |
|:---|:---|
| **触发时机** | BEFORE INSERT / UPDATE |
| **功能** | INSERT 时强制覆盖为 `now()`，UPDATE 时强制恢复为旧值 |
| **必需性** | 可选（推荐，作为最后一道防线） |
| **防护目标** | 防止应用层恶意或错误修改 `created_at` |
| **绑定示例** | `CREATE TRIGGER trg_department_audit_created_at BEFORE INSERT OR UPDATE ON department FOR EACH ROW EXECUTE FUNCTION audit_created_at();` |

#### 函数 5：`is_uuid_v7()`

```sql
CREATE OR REPLACE FUNCTION is_uuid_v7(p_uuid uuid)
RETURNS boolean AS $$
BEGIN
    RETURN p_uuid ~ '^[0-9a-f]{8}-[0-9a-f]{4}-7[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$';
END;
$$ LANGUAGE plpgsql IMMUTABLE STRICT PARALLEL SAFE;
```

| 项目 | 说明 |
|:---|:---|
| **触发时机** | 无（纯函数，用于 CHECK 约束或查询） |
| **功能** | 验证 UUID 是否为 v7 版本（时间有序 UUID） |
| **必需性** | 可选（按需启用） |
| **UUID v7 结构** | `xxxxxxxx-xxxx-7xx-xxxx-xxxxxxxxxxxx`（版本位=7，变体位=8/9/a/b） |
| **使用场景** | CHECK 约束、数据质量检查、查询验证 |
| **约束示例** | `CHECK (is_uuid_v7(id))`（业务表主键；`_by` 为 text 不适用） |
| **查询示例** | `SELECT * FROM department WHERE NOT is_uuid_v7(id);` |

## 1. `id` 字段 UUID v7 约束策略（业务表）

> **类型基准（v4.5）：** `_by` 字段为 **TEXT**（Logto 用户 id，21 位 nanoid），不适用 UUID v7 校验；
> UUID v7 策略仅针对业务表主键 `id`（默认值 `uuidv7()` 生成）。镜像表 `id` 为 Logto 同步的
> nanoid 字符串（text），同样不适用本策略。

### 1.1 策略选择

| 方案 | 优点 | 缺点 | 适用场景 |
|:---|:---|:---|:---|
| **A. 不约束** | 灵活、零开销 | 无法保证数据质量 | 快速迭代、信任应用层（`uuidv7()` 默认值已保证） |
| **B. 强制 CHECK** | 数据库层保证质量 | 限制边缘场景（如历史数据迁移） | 严格合规要求 |
| **C. 可选约束** | 按需启用 | 需要用户了解选项 | **推荐（默认）** |

### 1.2 推荐方案：可选约束

主键默认由 `uuidv7()` 生成，CHECK 作为最后防线，按需启用：

```sql
    -- 主键：UUID v7（时间有序）
    id UUID PRIMARY KEY DEFAULT uuidv7(),  -- 可选: CHECK (is_uuid_v7(id))
```

如需严格验证，请取消注释 CHECK，或建表后通过 ALTER TABLE 添加：

```sql
ALTER TABLE <表名> ADD CONSTRAINT chk_<表名>_id_uuid7
    CHECK (is_uuid_v7(id));
```

### 1.3 约束规则

- **业务表**：`id` 为 UUID v7（`uuidv7()` 默认值），CHECK 仅作最后防线
- **镜像表**：`id` 为 Logto nanoid（text），不适用本策略
- **历史数据兼容**：已存在的历史数据不受影响（仅新增/修改时触发约束）

## 2. 模板选择决策树

```
新建数据库对象需要审计字段吗？
│
├── 系统级表（cron_job_log）
│   └── ❌ 不需要审计字段
│       原因：系统任务写入，无用户上下文，审计无意义
│       注：sys_secret / sys_token_blacklist / sys_user_session 已移除
│          （密钥与令牌黑名单、会话交由 IdP 管理，不再自建表）
│
├── 审计日志表（audit_log）
│   └── ❌ 不需要审计字段
│       原因：审计日志本身记录变更，无需再审计
│       治理：业务角色禁 UPDATE/DELETE（追加保护）+ 分区/归档策略
│
├── 静态参考数据表（ip_geolite2_* / ip_region_v4）
│   └── ❌ 不需要审计字段
│       原因：外部数据源导入，审计在数据源/导入流程
│
├── IdP 镜像/同步表（users / tenants / role / organization_role / user_tenants）
│   └── ❌ 不套用本项目审计模板——完全以 Logto 同步数据为准：
│       仅保留 created_at（Logto createdAt）+ logto_updated_at / joined_at 同步元数据；
│       无 _by（写入者是 webhook，无用户语义）、无软删（Logto 删除 = 行删除）
│
├── 配置/字典表（app_config / dict_type / dict_data 等）
│   └── ✅ 推荐：模板 6（IAuditedObject）
│       原因：配置/字典变更安全敏感，需可追溯修改者（谁改了什么配置）
│
├── 关联表（M:N 关系表，如 user_role / iam_role_menu / user_position / iam_role_data_scope）
│   └── ⚠️ 推荐：模板 1（IHasCreationTime）或 模板 3（ICreationAuditedObject）
│       原因：关联表通常只需知道"何时创建"，无需修改/删除审计
│       实现：复合主键、硬删不软删、无 updated_at 触发器
│
├── 日志/事件表（login_log / webhook_event_log）
│   └── ⚠️ 推荐：模板 1（IHasCreationTime）
│       原因：只追加、不修改，无需软删除
│       防护：业务角色 REVOKE UPDATE/DELETE，写入走 SECURITY DEFINER 函数
│
├── 视图（VIEW）
│   └── ❌ 不需要审计字段
│       原因：视图是虚拟表，审计字段应在基表中
│
├── 核心业务表（department / position / user_profile 等）
│   └── ✅ 推荐：模板 10（IFullAuditedObject）⭐⭐
│       原因：完整生命周期追踪（创建+修改+删除）
│       注意：软删 + 唯一约束必须用部分唯一索引（WHERE deleted_at IS NULL）
│
└── 只读/缓存表（如物化视图、缓存表）
    └── ❌ 不需要审计字段
        原因：数据从其他表同步，审计应在源表
```

---

> **软删 vs 硬删判定原则（模板 10 与 6 的分界）：** ① 权限/安全目录（iam_menu、role）必须硬删——软删存在查询遗忘 `deleted_at` 过滤导致权限"复活"的 fail-open 风险；② 被存活业务行 FK 引用的实体（department、position 等）必须软删保引用完整性；③ 删除事件本身已由 `trg_audit_*` 触发器全量写入 audit_log（DELETE 的 old_data 落库），硬删不丢审计。
>
> **时间戳默认值提示：** 审计字段（created_at/updated_at）用 `now()`（事务开始时间，行业惯例）；日志表如需精确到每行写入时刻可用 `clock_timestamp()`。

## 4. 10 个接口各自的 PostgreSQL 字段定义

> **使用说明：** 建表时按需复制对应模板的字段代码块。
> **类型说明（v4.5）：** `_by` 字段为 **TEXT**（Logto 用户 id）；UUID v7 约束仅用于主键 `id`，见 §1。

**性质：** `CreationTime`
**PostgreSQL 字段：** `created_at`

```sql
    -- 审计字段：创建时间（由数据库默认值填充，应用层不应修改）
    -- 如需强制保护，请绑定 audit_created_at() 触发器
```

**PostgreSQL 字段：** `created_by`


### 接口 10：`IFullAuditedObject` ⭐⭐

**性质：** `CreationTime`, `CreatorId`, `LastModificationTime`, `LastModifierId`, `IsDeleted`, `DeletionTime`, `DeleterId`（继承 6 + 9）
**PostgreSQL 字段：** `created_at`, `created_by`, `updated_at`, `updated_by`, `deleted_at`, `deleted_by`

```sql
    -- ============================================================
    -- 【模板 10】接口 IFullAuditedObject（推荐：完整审计）
    -- 性质：CreationTime, CreatorId, LastModificationTime, LastModifierId,
    --        IsDeleted, DeletionTime, DeleterId
    -- PostgreSQL 实现：6 个字段（deleted_at 取代表示 IsDeleted + DeletionTime）
    -- 适用：核心业务实体，需要完整生命周期追踪（创建+修改+删除）
    -- ============================================================

    -- 审计字段：完整审计（创建 + 修改 + 软删除）
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    created_by TEXT,  -- Logto 用户 id（NULL=系统/同步创建）
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by TEXT,  -- Logto 用户 id（NULL=系统/同步修改）
    deleted_at TIMESTAMPTZ,
    deleted_by TEXT,  -- Logto 用户 id（NULL=系统/同步删除）
    -- 注释：created_at = 创建时间，不可变
    -- 注释：created_by = 创建者（NULL=系统创建）
    -- 注释：updated_at = 最后修改时间（触发器自动维护）
    -- 注释：updated_by = 最后修改者（应用层/触发器填充）
    -- 注释：deleted_at = 软删除时间（NULL=未删除）
    -- 注释：deleted_by = 删除者（应用层/触发器填充）
```

## 6. 触发器绑定（配合审计字段）

### 6.0 先分清两条审计链路（生产主链路 vs 字段自动填充）

| 链路 | 触发器 | 落点 | 用途 |
|:---|:---|:---|:---|
| **变更日志审计（生产主链路）** | `trg_audit_<表名>` → `audit_trigger_func('tenant_aware')` | `write_audit_log` → `audit_log`（old_data/new_data 全量 JSON） | 谁在何时改了什么——INSERT/UPDATE/DELETE 全覆盖 |
| **字段自动填充（可选辅助）** | §6.1-6.4：`update_updated_at()` / `audit_user_fields()` / `audit_deletion_user()` / `audit_created_at()` | 行内 `updated_at` / `_by` / `created_at` 字段 | 维护行内审计字段供查询/过滤，不落日志 |

现库业务表（department / dict_data / dict_type / iam_menu / iam_role_menu / position / user_position / user_profile / app_config）均挂 `trg_audit_*`（变更日志链路）；§6.1-6.4 的字段填充触发器按需追加绑定。镜像表不挂任何本项目审计触发器（见 §2 决策树）。

### 6.1 `updated_at` 自动维护（必需）

```sql
-- 每个使用 updated_at 的表都需要绑定此触发器
-- 函数 update_updated_at() 已在 Migration 001 中定义

CREATE TRIGGER trg_<表名>_updated_at
    BEFORE UPDATE ON <表名>
    FOR EACH ROW EXECUTE FUNCTION update_updated_at();
```

### 6.2 `created_by` / `updated_by` 自动填充（可选，推荐）

```sql
-- 可选：通过触发器自动维护 created_by / updated_by
-- 注意：需要从 JWT claims 中获取当前用户 ID（current_user_id() 函数已定义）
-- 注意：无 JWT 上下文时（如系统任务），自动设为 NULL

CREATE TRIGGER trg_<表名>_audit_user
    BEFORE INSERT OR UPDATE ON <表名>
    FOR EACH ROW EXECUTE FUNCTION audit_user_fields();
```

### 6.3 `deleted_by` 自动填充（可选，推荐）

```sql
-- 可选：通过触发器自动维护 deleted_by
-- 注意：仅在 deleted_at 从 NULL 变为非 NULL 时触发

CREATE TRIGGER trg_<表名>_audit_deletion
    BEFORE UPDATE ON <表名>
    FOR EACH ROW EXECUTE FUNCTION audit_deletion_user();
```

### 6.4 `created_at` 强制保护（可选，推荐）

```sql
-- 可选：通过触发器强制保护 created_at
-- INSERT 时强制覆盖为 now()，UPDATE 时强制恢复为旧值

CREATE TRIGGER trg_<表名>_audit_created_at
    BEFORE INSERT OR UPDATE ON <表名>
    FOR EACH ROW EXECUTE FUNCTION audit_created_at();
```

### 6.5 主键 UUID v7 严格验证（可选，按需启用）

```sql
-- 可选：通过 CHECK 约束强制主键为 UUID v7
-- 默认值 uuidv7() 已保证，CHECK 仅作最后防线（_by 为 text，不适用 v7 校验）

ALTER TABLE <表名> ADD CONSTRAINT chk_<表名>_id_uuid7
    CHECK (is_uuid_v7(id));
```

## 7. 查询辅助

### 7.1 软删除过滤（必须）

```sql
-- 所有查询软删除表时，必须添加此条件
-- WHERE deleted_at IS NULL

-- 示例：
SELECT * FROM <表名> WHERE deleted_at IS NULL;
```

### 7.2 查询已删除数据

```sql
-- 查询已软删除的数据
SELECT * FROM <表名> WHERE deleted_at IS NOT NULL;
```

### 7.3 创建过滤视图（可选）

```sql
-- 为高频查询的表创建自动过滤软删除的视图
CREATE OR REPLACE VIEW <表名>_active AS
SELECT * FROM <表名> WHERE deleted_at IS NULL;

-- 使用：
SELECT * FROM <表名>_active;
```

### 7.4 数据质量检查（可选）

```sql
-- 检查业务表 id 中是否有非 UUID v7 的数据（逐表执行，示例为 department）
SELECT count(*) AS total,
       count(*) FILTER (WHERE NOT is_uuid_v7(id)) AS invalid_uuid7
FROM department;

-- 镜像表 id 为 Logto nanoid（text），不做 v7 校验
```

## 9. 使用示例：创建新表时引用模板

### 9.1 示例：创建 `article` 表（文章管理，使用模板 10）

```sql
CREATE TABLE article (
    -- 主键
    id UUID PRIMARY KEY DEFAULT uuidv7(),
    
    -- 业务字段
    title VARCHAR(200) NOT NULL,
    content TEXT,
    author_name VARCHAR(50),
    status VARCHAR(20) NOT NULL DEFAULT 'draft' CHECK (status IN ('draft', 'published', 'archived')),
    tenant_id TEXT NOT NULL REFERENCES tenants(id) ON DELETE RESTRICT,  -- Logto 租户 nanoid
    
    -- 审计字段：模板 10（IFullAuditedObject）
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    created_by TEXT,  -- Logto 用户 id
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by TEXT,  -- Logto 用户 id
    deleted_at TIMESTAMPTZ,
    deleted_by TEXT   -- Logto 用户 id
);

-- 索引（PostgreSQL 标准写法）
CREATE INDEX idx_article_tenant ON article(tenant_id);
CREATE INDEX idx_article_status ON article(status);

-- 绑定触发器
CREATE TRIGGER trg_article_updated_at
    BEFORE UPDATE ON article
    FOR EACH ROW EXECUTE FUNCTION update_updated_at();

CREATE TRIGGER trg_article_audit_user
    BEFORE INSERT OR UPDATE ON article
    FOR EACH ROW EXECUTE FUNCTION audit_user_fields();

CREATE TRIGGER trg_article_audit_deletion
    BEFORE UPDATE ON article
    FOR EACH ROW EXECUTE FUNCTION audit_deletion_user();

-- 可选：主键 UUID v7 严格验证
-- ALTER TABLE article ADD CONSTRAINT chk_article_id_uuid7
--     CHECK (is_uuid_v7(id));

-- 启用 RLS
ALTER TABLE article ENABLE ROW LEVEL SECURITY;

CREATE POLICY article_tenant_isolation ON article
AS RESTRICTIVE
USING (tenant_id = current_tenant_id())
WITH CHECK (tenant_id = current_tenant_id());

-- 注释
COMMENT ON TABLE article IS '文章管理表';
COMMENT ON COLUMN article.deleted_at IS '软删除时间，NULL=未删除';
```

## 10. 总结

| 要点 | 说明 |
|:---|:---|
| **模板用途** | 不建表，仅作为字段参考片段 |
| **推荐模板** | 模板 10（IFullAuditedObject）—— 完整审计 |
| **核心字段** | `created_at`, `updated_at`, `deleted_at` + 可选 `_by` 字段 |
| **触发器** | `updated_at` 必须绑定 `update_updated_at()`；`_by` 字段推荐绑定 `audit_user_fields()` / `audit_deletion_user()` |
| **查询规范** | 所有业务查询必须加 `WHERE deleted_at IS NULL` |
| **外键策略** | `_by` 字段不强制外键约束（镜像表用户会物理删除，FK 会破坏审计留痕） |
| **NULL 语义** | `_by` 字段为 NULL 表示系统/同步/匿名操作 |
| **UUID v7 约束** | 可选约束（主键 `id`），通过 `is_uuid_v7()` 函数实现；`_by` 为 TEXT（Logto 用户 id）不适用 |
| **ISoftDelete 实现** | `deleted_at IS NOT NULL` 等价 `IsDeleted = true` |
| **IDataFilter 实现** | 通过 RLS 策略 + 手动过滤实现运行时软删除过滤 |
