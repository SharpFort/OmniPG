## 6. 核查规则与判定标准（055 实施依据）

1. **死端点判定**：path 不在 `api_v1_public` 暴露清单（13 个 rpc 源文件 + 21 个视图）→ DEAD。⚠️ `docs/开发实施方案/API速查表.md` 已过时（含 user_login_sso/health_check/create_user/kick_user 等已删端点），**不可作为暴露依据**；以 api_v1/public 目录 + 存量库 information_schema/pg_proc 实测为准（§4 SQL 自动判定）
2. **无码行**：api_code IS NULL → 按 D9 清除（不转换、不赋码）；其 role_api 绑定随行清除（超管短路兜底：role_super_admin 全部绑定丢失无实际影响；tenant_admin 绑定全在有码行）
3. **有码行转换**：同码 button 行存在 → 回填 api_url/api_method（成对，method 值域含 '*'）；不存在 → 按 api_group/menu_id 归属新建 button 行（menu_name=api.name、描述→remark、parent_id=归属目录）；**一码多行逐行映射不合并**
4. **授权转换**：iam_role_api 有码行绑定 → iam_role_menu 对应 button 行（逐行）；role_super_admin 绑定随行转换（或依赖超管短路不转换——055 实施时拍板，默认转换保持数据完整）
5. **055 后 button 行必带码**（040 CHECK）+ router/component 置空（D8 CHECK）+ api_method 成对值域（D6 CHECK）
