|:---|:---|

## 1. 验证项与判定标准

| # | 验证项 | 方法 | 判定标准（通过 = 方案 C 该环节成立） |
|:---|:---|:---|:---|
| V1 | **payload 结构** | 02 脚本步骤 2 后查 out/ | payload 含 `action/object/user/requestUri/response`，**无 `event` 字段**；`object` 是 JSON 字符串；`user` 是操作者用户名 |
| V2 | **add-role 事件 + users 完整性** | 02 步骤 2 | 事件触发；object 解析后含完整 `users` 数组（含挂载用户） |
| V3 | **update-role 事件 + users 完整性（关键）** | 02 步骤 3/4 | 挂/摘用户后事件触发；object 的 users 为**变更后全量**列表（diff 同步可行） |
| V4 | **update-role API 稳定性（硬前提）** | 02 步骤 3/4 的 HTTP 状态码 + UI 手工保存一次 | 直调与 UI 均返回 200/status:"ok"；**若复现 500 → 方案 C 分配同步分支否决**（见审查报告 H4） |
| V5 | **失败/越权请求是否触发事件** | 02 步骤 7（更新不存在的角色）；可选：普通用户 token 调 update-role | 事件仍触发且 `response` 含 `status:"error"` → **RPC 必须加 response 成败守卫**（预期：会触发） |
| V6 | **delete-role 事件** | 02 步骤 6 | 事件触发；object 含角色标识 |
| V7 | **角色改名事件（H7）** | 02 步骤 5 | 事件触发；object.name=新名；`requestUri` 含 `?id=org%2F旧名`（rename 处理依据） |
| V8 | **多角色 JWT roles 顺序（H1）** | 04 脚本（用户挂 2 个角色后） | 打印 roles 数组；确认顺序非稳定（建议记录：创建角色 B 前后 roles[0] 是否变化）→ 支撑 claim 稳定化决策 |
| V9 | **isEnabled=false 角色仍进 JWT（H9）** | 04 脚本（先禁用某角色） | 禁用角色仍在 roles 中 → RLS/插件必须过滤 isEnabled |
| V10 | **tokenFormat 凭据泄漏（H3）** | 04 脚本（默认格式）→ 配 JWT-Custom+tokenFields 后复跑 | 默认格式含 passwordSalt/totpSecret 等 → 必须 JWT-Custom；JWT-Custom 后 roles 仍为对象数组（`.roles[0].name` 兼容） |
| V11 | **SingleOrgOnly 行为（M1）** | webhook 开 SingleOrgOnly=true 重跑 V2；用 built-in admin 操作对照 | 业务 org 操作不触发（built-in admin）/触发（业务 admin）——确认部署用 SingleOrgOnly=false |
| V12 | **重试/Replay 乱序（H5）** | 停掉接收器触发事件 → 事件 Failed/Retrying → 重启接收器 → UI Replay | 旧事件后到；确认 diff 需顺序守卫 |
| V13 | **roles=[] 兜底（M6）** | 04 脚本（无角色用户） | roles=[] → PostgREST 回落 anon（42501）→ 确认保留全员默认角色约定 |

## 2. 执行顺序

```bash
cd scripts/verify-webhook

# 0) 起接收器（另开终端；WSL2 内 python3）
python3 01_receiver.py 8099
#    → Casdoor webhook URL 填 http://<本机可达地址>:8099/

# 1) 环境变量（按实际填写）
export CASDOOR_URL=http://localhost:8000
export ORG=omnipg
export ADMIN_USER=admin        # 业务 org 管理员
export ADMIN_PASS=***
export TEST_USER=omnipg/alice  # 已存在的普通用户
export CLIENT_ID=xxx           # 04 脚本用（password grant）
export CLIENT_SECRET=xxx
export USERNAME=omnipg/alice   # 04 脚本用（被测用户）
export PASSWORD=***

# 2) 触发角色事件（V1–V7）
bash 02_role_events.sh

# 3) 解析收到的 payload（V1–V7 判定）
bash 03_inspect_payloads.sh

# 4) JWT claims 检查（V8–V10、V13）
bash 04_jwt_claims.sh

# 5) 手工项：V4(UI 保存)、V11(SingleOrgOnly 开关)、V12(停接收器+Replay)
```
