# 05.3 — IP 归属数据链路（ip2region + GeoLite2 + 登录日志视图）

> **状态**：✅ 已实现（019/020/021/023/026 迁移，2026-08-05 定稿）
> **定位**：登录日志（Logto webhook PostSignIn）的 IP 归属解析——零后端（无外部 API、无常驻服务），全离线数据 + PG 内查询。
> **核心链路**：`Logto PostSignIn webhook → login_log 表（写入时解析快照）→ v_login_log 视图（查询时实时关联两张 IP 表）`

---

## 一、数据源与版本（2026-08-05 实测核实）

| 数据源 | 版本/规模 | 字段 | 授权 |
|:---|:---|:---|:---|
| **ip2region 免费版**（GitHub `lionsoul2014/ip2region` `data/ipv4_source.txt`） | **517,743 行**（实测下载核实） | 7 字段：`起始IP\|结束IP\|国家\|省\|市\|ISP\|iso-code` | 免费，社区维护 |
| **ip2region 商业版**（官网 `ip2region.net/doc/data/ipv4_base` **V4-基础版**） | 22,883,308 行 / 3.4G / 满载 xdb 266MB | 10 字段（**含行政区码、电话区号**），IP 段切分更细 | **付费商用**（数据服务购买） |
| **GeoLite2-City**（MaxMind 官方 CSV） | Blocks-IPv4 + Locations-zh-CN（全球，含经纬度/时区） | network/geoname_id/latitude/longitude/timezone/city_name 等 | 免费账号 license key，30 天更新 |

**结论**：官网未找错——免费版与商业版是**数据粒度差异**（免费 52 万行粗粒度合并段、中国到市/全球到国家地区级；商业 2288 万行细粒度 + 行政区码/电话区号）。国内应用免费版已够用，Geo Lite2 兜底补全球经纬度。

**为什么不走 xdb + golang 查询客户端**：官方 `binding/golang`（service.NewV4Config + Search）技术上成熟（微秒级），但**需常驻 Go 服务**——违背零后端架构（PG-only + PostgREST）；且 webhook 写库时无法同步解析（引入网络依赖），查询时 join 需 Go 参与。**txt → PG 表 + SQL 查询毫秒级**是零后端正确形态。

## 二、表结构（两张离线 IP 表）

### 2.1 `ip_region_v4`（019 建表，ip2region 数据）

```sql
CREATE TABLE ip_region_v4 (
    id         BIGSERIAL PRIMARY KEY,
    start_ip   INET NOT NULL,          -- 起始 IP（段）
    end_ip     INET NOT NULL,          -- 结束 IP（段）
    country    TEXT NOT NULL,
    province   TEXT,                   -- 省（国家段为 NULL/空）
    city       TEXT,                   -- 市
    isp        TEXT,                   -- 运营商（中国段有效）
    iso_code   TEXT,                   -- ISO 3166-1 alpha-2
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (start_ip, end_ip)
);
CREATE INDEX idx_ip_region_v4_range ON ip_region_v4 (start_ip, end_ip);  -- 范围查询
```

### 2.2 `ip_geolite2_city`（021 建表，GeoLite2-City 数据）

```sql
CREATE TABLE ip_geolite2_city (
    network         CIDR PRIMARY KEY,  -- 网络块（如 1.0.0.0/24）
    geoname_id      BIGINT,
    latitude        FLOAT8,
    longitude       FLOAT8,
    accuracy_radius INT,
    timezone        TEXT,
    country_name    TEXT,
    city_name       TEXT
);
-- 查询用包含操作符：WHERE network >>= ip::cidr ORDER BY masklen(network) DESC LIMIT 1
```

### 2.3 staging 表（导入中转）
`ip_geolite2_blocks`（Blocks-IPv4 全 10 列）+ `ip_geolite2_locations`（Locations-zh-CN 全 14 列）——下载 CSV 先 COPY staging，再由 `import_geolite2_city()` 函数 join 转换进正式表。

## 三、查询函数

### 3.1 `ip2region(ip inet) returns text`（020 建，021 加 family 过滤）

```sql
-- ip_region_v4 范围查询：国家|省|市|ISP；IPv6 返回 NULL（family 过滤）
SELECT country || '|' || province || '|' || city || '|' || isp
FROM ip_region_v4 WHERE family(ip)=4 AND start_ip <= ip AND end_ip >= ip
ORDER BY start_ip DESC LIMIT 1;
```

### 3.2 `geo_locate(ip inet) returns jsonb`（021 建，**ip2region 优先 → GeoLite2 兜底**）

```sql
-- 返回: {"source": "ip2region"|"geolite2", "region", "latitude", "longitude",
--        "timezone", "country", "city"}
-- 逻辑: ① ip2region 命中 → source=ip2region（含 region 字符串）
--       ② 未命中（含全部 IPv6）→ GeoLite2 CIDR 包含查询（network >>= ip::cidr）
-- 查询顺序: ip2region 优先（中国精度高、含 ISP）→ GeoLite2 兜底（全球经纬度/时区）
```

## 四、登录日志视图（Logto 登录信息 × 两张 IP 表）

### 4.1 `v_login_log`（026 定稿：v_sys_login_log 去 sys_ 前缀）

```sql
CREATE VIEW api_v1_public.v_login_log AS
SELECT l.id, l.tenant_id, l.user_id, l.username, l.login_type, l.result,
       l.fail_reason, l.ip, l.user_agent,
       l.region                 AS region_snapshot,  -- 写入时 ip2region 快照（历史不变）
       g.region                 AS region_live,     -- 查询时实时归属（数据更新即生效）
       g.source                 AS geo_source,      -- ip2region / geolite2
       g.latitude, g.longitude, g.timezone,         -- GeoLite2 提供（ip2region 无经纬度）
       l.logto_event, l.created_at
FROM login_log l
LEFT JOIN LATERAL geo_locate(l.ip) g ON true;
```

### 4.2 数据流

```
Logto PostSignIn webhook（userIp/userAgent/userId，payload 顶层平铺）
        │  sync_login_log_write(payload)   [020/023]
        ▼
login_log 表（tenant_id=NULL，region=写入时 ip2region 解析快照）
        │  v_login_log 查询时 LATERAL geo_locate(l.ip)
        ▼
api_v1_public.v_login_log  ← 登录信息 + ip2region 归属 + GeoLite2 经纬度/时区
```

### 4.3 双保险设计
- **region_snapshot**：写入时固化——历史日志不受后续数据更新影响（审计一致性）
- **region_live**：查询时实时 join——数据更新后新查询自动用新归属
- 管理端/审计查询直接读 `v_login_log` 单视图，无需再 join

## 六、查询示例

```sql
-- 单 IP 定位
SELECT geo_locate('223.247.32.216'::inet);
-- {"source":"ip2region","region":"中国|四川省|成都市|电信","latitude":30.57,
--  "longitude":104.06,"timezone":"Asia/Shanghai","country":"中国","city":"成都"}

-- IPv6（ip2region 无数据 → GeoLite2 兜底）
SELECT geo_locate('240e:3b7::1'::inet);
-- {"source":"geolite2","region":null,"latitude":...,"longitude":...,"timezone":...}

-- 登录日志 + 地理（管理端/审计直查）
SELECT user_id, username, ip, region_snapshot, region_live,
       geo_source, latitude, longitude, timezone, created_at
FROM api_v1_public.v_login_log
WHERE result = 'success' ORDER BY created_at DESC LIMIT 10;

-- 租户维度登录日志（权限点 sys:login-log:list + 本租户成员过滤，023）
SELECT * FROM api_v1_public.rpc_search_login_logs('', 'success', NULL, NULL, 20, 0);
```
