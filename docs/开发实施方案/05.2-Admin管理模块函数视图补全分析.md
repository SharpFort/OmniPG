## 二、P0 核心缺口（3 项，安全/审计完整性）

> **2026-08-04 已全部实现（023 迁移）** ✅

### 2.1 `has_permission(code)` — ✅ 已实现（023 §3）

**现状（实现前）**：009 注释、05 文档 §6.3 设计均有"has_permission(code)"，但 `db/` 全库搜索 **无 CREATE FUNCTION**。所有管理 RPC 的权限门槛形同虚设（当前仅靠网关 required_roles 粗粒度）。

**实现（023）**：
```sql
-- 权限判定：超管短路 + claims roles ∩ (iam_role_api → iam_api.api_code)
CREATE OR REPLACE FUNCTION has_permission(p_code text) RETURNS boolean
LANGUAGE plpgsql STABLE SECURITY DEFINER SET search_path = public, pg_temp AS $$
DECLARE v_roles text[];
BEGIN
    IF p_code IS NULL OR p_code = '' THEN RETURN false; END IF;
    IF is_super_admin() THEN RETURN true; END IF;
    SELECT ARRAY(SELECT jsonb_array_elements_text(
        current_setting('request.jwt.claims', true)::jsonb->'roles')) INTO v_roles;
    IF v_roles IS NULL OR cardinality(v_roles) = 0 THEN RETURN false; END IF;
    RETURN EXISTS (
        SELECT 1 FROM iam_role_api ra
        JOIN iam_api a ON a.id = ra.api_id
        WHERE ra.role_code = ANY (v_roles)
          AND a.api_code = p_code AND a.is_active);
END $$;
```
配套：**iam_api 加 `api_code` 列**（023 §2，权限码与 iam_menu.perms 同语义；实现前 iam_api 无权限码字段，has_permission 无法匹配）。

### 2.2 审计触发器覆盖补全 — ✅ 已实现（023 §4）

**现状（实现前）**：data_change 审计触发器只挂 department / iam_role_api / iam_role_menu。

**实现（023）**：补挂 **8 张**（系统管理 6 + 授权 2）：
- 系统管理：dict_type / dict_data / position / user_position / app_config / user_profile
- 授权：iam_menu / iam_api
- 镜像表（users/tenants/user_tenants/role）**不挂**（Logto 权威，webhook 事件可追溯，避免高频 upsert 审计爆炸）
- 全部 `audit_trigger_func('tenant_aware')` 统一模式；原有 3 + 新增 8 = **11 个审计触发器**

### 2.3 登录日志租户查询 RPC — ✅ 已实现（023 §5）

**现状（实现前）**：`v_login_log` 已可查（021），但 RLS 是 `is_super_admin() OR tenant_id = current_tenant_id() OR user_id = current_user_id()`——**tenant_id 为 NULL**（PostSignIn 无组织上下文），租户管理员查不到本租户用户的登录记录。

**实现（023）**：`api_v1_sys.rpc_search_login_logs(p_user_id, p_result, p_from, p_to, p_limit, p_offset)`——SECURITY DEFINER + `has_permission('sys:login-log:list')` 门槛（42501 拒绝）+ 内部按 `user_tenants`（当前租户成员）过滤；超管豁免；返回与 search_users 同构分页 json。

## 四、架构决策点（2 项，2026-08-04 已拍板）

### 4.1 管理端写 Logto 的路径 — ✅ **放弃**（用户拍板）

**决策**：建号/禁用/角色分配**不放在业务管理端**，直接在 **Logto Console 管理**，业务端仅经 webhook 同步镜像。原 05 §12 P1-10"管理端走 Management API"取消。

**理由**：零后端下前端直持 M2M token 存在凭据暴露风险（XSS 窃取、全租户权限）；APISIX 代理注入方案（原推荐 A）增加网关复杂度；低频管理操作（建号/禁用/角色分配）用 Logto Console 完全可承受。

**保留**：P2 备选（若未来需要自研管理 UI 操作 Logto，再评估 APISIX 代理注入 M2M token 方案）。

### 4.2 iam_menu 按钮级字段 — ✅ **已实现（022 迁移）**

对照 RuoYi `sys_menu`（menu_type/perms/component/visible，源码已核实），022 已加列：

```sql
ALTER TABLE iam_menu
    ADD COLUMN menu_type  text NOT NULL DEFAULT 'menu',  -- directory/menu/button
    ADD COLUMN perms      text,                          -- 权限码（sys:user:delete，对应 iam_api.api_code）
    ADD COLUMN component  text,                          -- 前端组件路径
    ADD COLUMN is_visible boolean NOT NULL DEFAULT true;
```

前端：目录/菜单走 get_user_menu 树；按钮级由 `has_permission(perms)` 控制（登录时一次性拉取权限码集合）。
