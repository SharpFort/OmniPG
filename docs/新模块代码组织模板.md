# 新模块代码组织模板（直接引用版）

> **适用：** 在 `projects/` 下创建新业务模块（如 `orders`、`products`）  
> **铁律：SQL 中必须显式写 Schema 前缀，文件路径 ≠ 数据库位置**  
> **引用文档：** `Schema隔离实施方案.md`、`02-数据库建模-审计接口与字段模板完整参考-v4.3.md`、`14-项目代码组织结构-v2.md`

---

## 一、目录结构

```
projects/my-project/
├── migrations/{module}/                # DDL 增量迁移（只增不改）
│   ├── 20260728000001_create_schema.sql
│   └── 20260728000002_init_tables.sql
│
├── src/{module}/                       # 幂等源码（CREATE OR REPLACE）
│   ├── _init_schema.sql                # Schema 创建 + 权限
│   ├── functions/
│   ├── views/
│   ├── triggers/
│   └── types/
│
└── api_v1/{module}/                    # API 暴露层
    ├── views/                          # 对外视图（脱敏）
    └── rpc/                            # 对外 RPC 函数
```

---

## 二、Schema 隔离规则

| 规则 | 说明 |
|:---|:---|
| **新模块必须创建独立 Schema** | `CREATE SCHEMA IF NOT EXISTS {module}` |
| **sys 模块保持在 public** | 不创建新 Schema，权限直接在 public 设置 |
| **SQL 必须写 Schema 前缀** | `CREATE TABLE {module}.orders (...)` 而非 `CREATE TABLE orders` |
| **文件路径不决定 Schema** | 文件放 `src/orders/` 不会自动创建到 `orders` Schema |
| **search_path 设置** | `SET search_path = {module}, public, pg_temp` |

## 三、审计字段选择（决策树）

```
需要审计字段吗？
│
├── 系统级表（黑名单、会话、日志）→ ❌ 不需要
├── 审计日志表本身               → ❌ 不需要
├── 配置/字典表                  → ⚠️ 模板 1 或 6
├── M:N 关联表                   → ⚠️ 模板 1（仅 created_at）
└── 核心业务表                   → ✅ 模板 10（完整审计）⭐
```

### 模板 10：IFullAuditedObject（推荐核心业务表）

```sql
-- 直接复制此模板，替换 {module} 为你的模块名
CREATE TABLE {module}.orders (
    id UUID PRIMARY KEY DEFAULT uuidv7(),
    
    -- 业务字段
    order_no VARCHAR(50) NOT NULL,
    amount DECIMAL(12,2) NOT NULL DEFAULT 0,
    
    -- 审计字段（完整审计：创建+修改+软删除）
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    created_by UUID,  -- 可选: CHECK (created_by IS NULL OR is_uuid_v7(created_by)),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by UUID,  -- 可选: CHECK (updated_by IS NULL OR is_uuid_v7(updated_by)),
    deleted_at TIMESTAMPTZ,
    deleted_by UUID,  -- 可选: CHECK (deleted_by IS NULL OR is_uuid_v7(deleted_by)),
    
    -- 跨模块外键（引用 public 的系统表）
    CONSTRAINT fk_orders_user_id 
        FOREIGN KEY (user_id) REFERENCES public.sys_user(id) ON DELETE CASCADE
);
```

### 模板 6：IAuditedObject（无需软删除的表）

```sql
created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
created_by UUID,
updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
updated_by UUID,
```

### 模板 1：IHasCreationTime（关联表/日志表）

```sql
created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
```

## 四、各路径 Schema 前缀速查

| 文件路径 | SQL 中前缀 | 示例 |
|:---|:---|:---|
| `migrations/{module}/001.sql` | **需要** `{module}.` | `CREATE TABLE {module}.orders (...)` |
| `src/{module}/functions/*.sql` | **需要** `{module}.` | `CREATE FUNCTION {module}.create_order()` |
| `src/{module}/views/*.sql` | **需要** `{module}.` | `CREATE VIEW {module}.v_summary AS ...` |
| `src/{module}/triggers/*.sql` | **需要** `{module}.` | `CREATE TRIGGER ... ON {module}.orders` |
| `src/{module}/types/*.sql` | **需要** `{module}.` | `CREATE TYPE {module}.order_status AS ENUM` |
| `api_v1/{module}/views/*.sql` | **不需要**（已在 api_v1_{module}） | `CREATE VIEW api_{module}.v_orders AS ...` |
| `api_v1/{module}/rpc/*.sql` | **不需要** | `CREATE FUNCTION api_{module}.checkout()` |

## 五、跨 Schema 引用规则

```sql
-- ✅ 允许：业务模块引用 public 的系统表
ALTER TABLE {module}.orders 
ADD CONSTRAINT fk_user_id 
FOREIGN KEY (user_id) REFERENCES public.sys_user(id) ON DELETE CASCADE;

-- ✅ 允许：业务模块之间互引
ALTER TABLE {module}.order_items 
ADD CONSTRAINT fk_product_id 
FOREIGN KEY (product_id) REFERENCES inventory.products(id);

-- ✅ API 层引用业务 Schema
CREATE OR REPLACE VIEW api_v1_{module}.v_orders AS
SELECT id, order_no, amount, created_at
FROM {module}.orders
WHERE deleted_at IS NULL;
```

## 六、完整建表示例

```sql
-- file: projects/my-project/migrations/orders/20260728000001_create_schema.sql

-- 1. 创建 Schema
CREATE SCHEMA IF NOT EXISTS orders;
COMMENT ON SCHEMA orders IS '订单模块';

-- 2. 创建表（必须写 orders. 前缀）
CREATE TABLE orders.orders (
    id UUID PRIMARY KEY DEFAULT uuidv7(),
    order_no VARCHAR(50) NOT NULL UNIQUE,
    user_id UUID NOT NULL REFERENCES public.sys_user(id) ON DELETE CASCADE,
    total_amount DECIMAL(12,2) NOT NULL DEFAULT 0,
    status VARCHAR(20) NOT NULL DEFAULT 'pending',
    
    -- 审计字段
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    created_by UUID,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by UUID,
    deleted_at TIMESTAMPTZ,
    deleted_by UUID
);

-- 3. 创建索引
CREATE INDEX idx_orders_user_id ON orders.orders(user_id);
CREATE INDEX idx_orders_status ON orders.orders(status) WHERE deleted_at IS NULL;

-- 4. 启用 RLS
ALTER TABLE orders.orders ENABLE ROW LEVEL SECURITY;

CREATE POLICY tenant_isolation ON orders.orders
    USING (tenant_id = current_setting('app.current_tenant')::uuid);

-- 5. 权限
GRANT USAGE ON SCHEMA orders TO app_owner;
GRANT ALL ON ALL TABLES IN SCHEMA orders TO app_owner;
GRANT USAGE ON SCHEMA orders TO authenticated;
GRANT SELECT ON ALL TABLES IN SCHEMA orders TO authenticated;
```

```sql
-- file: projects/my-project/src/orders/_init_schema.sql
-- 幂等：可重复执行
CREATE SCHEMA IF NOT EXISTS orders;
GRANT USAGE ON SCHEMA orders TO app_owner;
GRANT ALL ON ALL TABLES IN SCHEMA orders TO app_owner;
GRANT USAGE ON SCHEMA orders TO authenticated;
GRANT SELECT ON ALL TABLES IN SCHEMA orders TO authenticated;
GRANT EXECUTE ON ALL FUNCTIONS IN SCHEMA orders TO authenticated;
```

```sql
-- file: projects/my-project/src/orders/functions/create_order.sql
CREATE OR REPLACE FUNCTION orders.create_order(
    p_user_id UUID,
    p_items JSONB
)
RETURNS UUID
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = orders, public, pg_temp
AS $$
DECLARE
    v_order_id UUID;
BEGIN
    INSERT INTO orders.orders (user_id, status)
    VALUES (p_user_id, 'pending')
    RETURNING id INTO v_order_id;
    
    -- 插入订单明细...
    
    RETURN v_order_id;
END;
$$;
```

```sql
-- file: projects/my-project/src/orders/triggers/trg_orders_updated_at.sql
CREATE TRIGGER trg_orders_updated_at
    BEFORE UPDATE ON orders.orders
    FOR EACH ROW EXECUTE FUNCTION public.update_updated_at();
```

```sql
-- file: projects/my-project/api_v1/orders/views/v_my_orders.sql
CREATE OR REPLACE VIEW api_v1_orders.v_my_orders AS
SELECT 
    o.id,
    o.order_no,
    o.total_amount,
    o.status,
    o.created_at
FROM orders.orders o
WHERE o.deleted_at IS NULL
  AND o.user_id = current_user_id();
```

```sql
-- file: projects/my-project/api_v1/orders/rpc/rpc_create_order.sql
CREATE OR REPLACE FUNCTION api_v1_orders.rpc_create_order(
    p_items JSONB
)
RETURNS JSON
LANGUAGE sql
SECURITY DEFINER
SET search_path = orders, public, pg_temp
AS $$
SELECT json_build_object(
    'order_id', orders.create_order(current_user_id(), p_items)
);
$$;
```

## 七、部署检查清单

| # | 检查项 | 文件 |
|:---|:---|:---|
| 1 | PostgREST `db-schemas` 添加 `api_v1_{module}` | `postgrest.conf` |
| 2 | PostgREST `db-extra-search-path` 添加 `{module}` | `postgrest.conf` |
| 3 | APISIX 路由添加 `/api/v1/{module}/*` → `/api_v1_{module}/*` | `apisix.yaml` |
| 4 | Makefile `apply-src` 扫描路径包含 `projects/` | `Makefile` |
| 5 | 所有 SQL 文件显式写了 Schema 前缀 | 代码审查 |

## 八、部署执行顺序

```bash
make dev-env           # 1. 启动环境
dbmate up              # 2. 执行所有 migrations（建表）
make apply-src         # 3. 刷入 src 源码（函数/视图/触发器）
make apply-api         # 4. 刷入 api_v1 暴露层
# 5. 重启 PostgREST + 重载 APISIX 配置
```

---

**一句话总结：文件路径是给人看的，Schema 前缀是给 PostgreSQL 看的。无论文件放哪个文件夹，SQL 中必须写 `{module}.` 前缀。**
