## 2. ⚠️ 权限码前缀矛盾（需要你裁决，唯一"代码不如库"的点）

- **库中权限点数据**：`iam_menu.api_code` = `public:*`（`public:import`、`public:config:write`…共 23 个，055 迁移已收敛）
- **代码侧 6 个 RPC 门槛码** = `sys:*`：
  - `rpc_import_csv` → `sys:import`
  - `rpc_update_config` → `sys:config:write`
  - `rpc_list_tenants` → `sys:tenant:list`
  - `rpc_list_tenant_members` → `sys:tenant-member:list`
  - `rpc_get_user_roles` → `sys:tenant-member:list`
  - `rpc_search_login_logs` → `sys:login-log:list`
- **055 D11 拍板（2026-08-12）**：权限码命名空间统一 `sys:` → `public:`（05.4 文档 §4.1/P-6 记录）
- **05.4 文档内部自相矛盾**：§4.1/P-6 写"统一 public:*"，§4.2 却写 `require_permission('sys:config:write'/'sys:import')`（8-14 核对更新时漏改）
- **后果**：`has_permission()` 是精确匹配（`iam_menu.api_code = p_code`，无前缀归一化）。若把代码侧函数部署到库，**门槛码 sys:\* 全部匹配失败 → 除超管外所有 RPC 调用被 42501 拒绝**。
- **现状**：库中函数（旧版）门槛是 `public:*`，与库中权限点 `public:*` 匹配 → 当前库能正常工作。

**裁决选项**：
- **A（推荐，符合 055 拍板）**：代码侧 6 个函数门槛码改回 `public:*`（一行改动 ×6），并修 05.4 §4.2 文档矛盾。
- **B**：推倒 055 拍板，改库中权限点数据 `public:*` → `sys:*`（新迁移，涉及 iam_menu 23 行 + 可能前端依赖）。**不推荐**：055 D11 已拍板 public:* 且与端点路径对齐，反转代价大。
