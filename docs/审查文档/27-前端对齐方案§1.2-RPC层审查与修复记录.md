## 二、关键事实核实（官方依据）

### 2.1 Logto webhook 事件表（docs.logto.io/zh-CN/developers/webhooks/webhooks-events，2026-08-07 抓取）

- User：User.Created / User.Deleted / User.Data.Updated / User.SuspensionStatus.Updated
- Role：Role.Created / Role.Deleted / Role.Data.Updated / Role.Scopes.Updated
- Organization：Organization.Created / Data.Updated / Deleted / Membership.Updated
- Management API 事件映射表：`POST /roles → Role.Created`、`PATCH /roles/:id → Role.Data.Updated`、`POST /roles/:id/scopes → Role.Scopes.Updated`、`PATCH /users/:userId/is-suspended → User.SuspensionStatus.Updated`
- **`PUT /users/:userId/roles`（用户-角色绑定）不触发任何事件** → user_role 镜像无法 webhook 驱动

**结论**：user_role 表（024）的维护只能依赖登录链路（JWT claims 全量覆盖）。035 将 JIT 覆盖并入 `ensure_user()`（前端登录回调已调），删除独立 RPC——业务端零主动同步，完全符合"利用 Logto 特性"原则。

### 2.2 omni_csv 官方能力（docs.omnigres.org/omni_csv/，2026-08-07 抓取）

- `omni_csv.csv_info(csv text)` — 列结构探测
- `omni_csv.parse(csv text)` — CSV → records（**需静态列结构** `as t(col text,...)`，对"任意表"通用导入不友好）
- `omni_csv.csv_agg(record)` — **聚合函数，records → CSV 字符串（含转义）**——24 号文档"序列化"说法成立

### 2.3 export_csv 现状（半成品确证）

```sql
-- rpc_export_csv.sql（029 版）核心
EXECUTE v_query;  -- COPY (SELECT %s FROM api_v1_public.%I WHERE %s) TO STDOUT
RETURN format('Use GET /api_v1_public/%s?select=%s to fetch data as JSON...', ...);
```

- **返回提示文本而非数据**（PostgREST 不支持流式 COPY，函数从未真正导出过）
- SECURITY DEFINER + `p_columns`/`p_filter` 裸 SQL 拼接 = 注入面（DEFINER 绕过 RLS）
- 前端实际导出路径 = `GET /api_v1_public/{view}?select=...`（PostgREST 原生：RLS 生效、Range 分页、max-rows=1000 兜底）+ 前端拼 CSV

## 三、决策记录

| 决策 | 内容 | 理由 |
|:---|:---|:---|
| D-1 | **export_csv 删除**（不走 omni_csv 补全） | 半成品 + 注入面 + PostgREST 不支持流式 COPY（text 返回需 JSON 解包，体验差）；GET /view 是零后端正统导出路径 |
| D-2 | **omni_csv 由 P0 必装降级为暂不引入**（修订 24 号文档） | 原 P0 理由（修 export_csv 半成品）随 D-1 消失；import_csv 保留 JSON 入口（前端 CSV→JSON 已做解析）；等"前端直传 CSV 文件"需求再装 |
| D-3 | **import_csv 保留通用命名 + 安全重写** | 通用函数（非页面专属），白名单显式限定业务自主表 7 张：department/position/user_position/dict_type/dict_data/iam_menu/iam_api；jsonb_populate_record 参数化（类型安全、列名安全、JSON null→NULL、per-row 错误收集保留） |
| D-4 | **rpc_sync_user_roles 删除，JIT 并入 ensure_user** | Logto 无角色绑定 webhook 事件（§2.1）；登录 JWT = Logto 权威快照推送；前端零额外调用；管理端"查某用户角色"走 v_user_roles/v_role_users（数据 = 各用户最近登录时快照，可接受）；P2 对账任务保留为可选兜底 |
| D-5 | **分页上限统一 100** | RPC 返回单一 JSON payload，PostgREST 无法 Range 分页 → p_limit/p_offset 是唯一正确模式；页面 10-50 条 + offset 翻页足够；防误传大 limit 拉全表。GET /view 才用 PostgREST 原生分页（max-rows=1000 配置兜底） |
| D-6 | **tenant_admin 补绑租户查看权限点** | 项目段租户仅查看：sys:tenant:list + sys:tenant-member:list；sys:login-log:list 保持超管专属（登录日志敏感，前端降级提示设计保留） |
| D-7 | **统一权限门槛三档 helper** | 🟢 无门槛（INVOKER+RLS）/ 🔐 权限点（DEFINER+require_permission）/ 👑 超管（DEFINER+require_super_admin）；本轮重写函数应用，其余 20+ CRUD RPC 渐进统一 |
