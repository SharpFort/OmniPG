## 二、核心踩坑记录

### 1. APISIX standalone 模式必须 `#END`

**坑**: `apisix.yaml` 文件末尾没有 `#END` 标记符，导致 APISIX 启动后路由全部 404。

**发现过程**: 反复重启容器 → 查看 `docker logs` → 发现 `config_yaml.lua` 的 `wait for more time` 警告 → 最终定位到 `missing valid end flag` 错误。

**教训**: APISIX standalone 模式（`config_provider: yaml`）**严格要求** `apisix.yaml` 末尾有 `#END`。这是官方文档中未明确标注的隐藏要求。

```yaml
# apisix.yaml 末尾必须加
routes: ...
upstreams: ...
#END    ← 不能少！
```

---

### 2. APISIX Admin API 在 standalone 模式下不可用

**坑**: 访问 `http://192.168.0.128:9180/` 提示"当前无法使用此页面"。

**原因**: `APISIX_STAND_ALONE=true` 是 data plane only 模式，Admin API 在该模式下**官方明确不支持**。

**三种部署模式对比**:

| 模式 | 配置存储 | Admin API (9180) | 适用场景 |
|:---|:---|:---|:---|
| **traditional** | etcd | ✅ 可用 | 生产环境，动态配置 |
| **standalone** | `apisix.yaml` | ❌ 不可用 | 轻量部署，无 etcd 依赖 |
| **decoupled** | etcd（控制面/数据面分离） | ✅ 可用 | 大规模集群 |

**结论**: 这是**预期行为**，不是故障。如果需要 Admin API，需要切换到 traditional 模式（依赖 etcd）。

---

### 3. APISIX 调试模式（debug.yaml）

**用途**: 排查路由匹配问题、插件执行顺序、变量值等。

**基本调试模式**:
```yaml
basic:
  enable: true
#END
```
效果：在 HTTP 响应头 `Apisix-Plugins` 中显示当前路由启用的插件列表。

**高级调试模式**:
```yaml
http_filter:
  enable: true
  enable_header_name: X-APISIX-Dynamic-Debug
#END
```
效果：对携带 `X-APISIX-Dynamic-Debug: foo` 的请求，在 error.log 中打印该请求经过的所有插件及执行顺序。

**验证方法**:
```bash
# 基本模式 - 查看响应头
curl -s -D- http://localhost:9080/healthz | grep Apisix-Plugins

# 高级模式 - 查看 error.log
curl -s http://localhost:9080/healthz -H 'X-APISIX-Dynamic-Debug: test'
docker logs app-apisix 2>&1 | grep trace_plugins_info_for_debug
```

### 4. Windows 端口 80 被 dllhost.exe 占用

**坑**: WSL2 中 Nginx 配置 `listen 80` 后，Windows 浏览器访问 `localhost` 显示的是 IIS 默认页。

**原因**: Windows 主机的 PID 26268 (dllhost.exe) 占用了 80 端口。

**解决**: 改为 `listen 8080`，通过 `http://192.168.0.128:8080` 访问。

---

### 5. Docker 容器间网络通信

**坑**: PostgREST 容器使用 `pgbouncer:6432` 连接数据库，但 pgbouncer 不在同一 Docker 网络。

**解决**: 改用 `host.docker.internal:6432` 通过宿主机网络访问 pgbouncer。

**教训**: Docker Compose 中不同服务要通信，必须在同一 network，或使用 `host.docker.internal` 走宿主机。

---

### 6. 密码特殊字符导致 psql 认证失败

**坑**: `apply-src.sh` 使用 `psql "$DB_URL"` 方式传递密码，密码中的特殊字符解析失败。

**解决**: 使用 `PGPASSWORD` 环境变量：
```bash
export PGPASSWORD='your_password'
psql -h 127.0.0.1 -U app_owner -d app_db -f file.sql
```

---

### 7. CORS 跨域问题

**坑**: Swagger UI 在 Windows 浏览器中打开，但请求被 CORS 阻止。

**原因**: Swagger UI 容器内 `API_URL=http://localhost:3001/` 指向容器内部，Windows 无法解析。

**解决**: 改为 WSL2 IP `http://192.168.0.128:3001/`。

---

### 8. PostgreSQL 权限链

**坑**: PostgREST 返回 `permission denied to set role "web_anon"`。

**原因**: `authenticator` 角色需要被显式授予 `web_anon` 角色。

**解决**:
```sql
GRANT web_anon TO authenticator;
GRANT USAGE ON SCHEMA api_v1_sys TO authenticator;
GRANT ALL ON ALL TABLES IN SCHEMA api_v1_sys TO authenticator;
GRANT EXECUTE ON ALL FUNCTIONS IN SCHEMA api_v1_sys TO authenticator;
```

---

### 9. Syncer 8080 端口冲突

**坑**: Docker Compose 中 syncer 服务映射了 8080 端口，与 WSL2 Nginx/Pigsty 冲突。

**解决**: 移除 syncer 的 `ports: - "8080:8080"`，改为仅通过容器内部网络访问。

## 四、一键启动命令

```bash
# WSL2 中执行
cd ~/OmniPG

# 1. 启动数据库基础设施
bash scripts/deploy-infra.sh

# 2. 刷入数据库源码
export PGPASSWORD=dev_password_change_me
for f in $(find db/src -name '*.sql' -not -name '_*' | sort); do
  psql -h 127.0.0.1 -U app_owner -d app_db -v ON_ERROR_STOP=0 -f "$f"
done

# 3. 启动网关层
cd gateway
docker compose up -d

# 4. 手动启动 APISIX（如果 compose 有问题）
docker stop app-apisix && docker rm app-apisix
docker run -d --name app-apisix \
  --network gateway_app-net \
  -p 9080:9080 -p 9443:9443 -p 9180:9180 \
  -e APISIX_STAND_ALONE=true \
  -v $(pwd)/apisix/config.yaml:/usr/local/apisix/conf/config.yaml:ro \
  -v $(pwd)/apisix/apisix.yaml:/usr/local/apisix/conf/apisix.yaml:ro \
  -v $(pwd)/apisix/debug.yaml:/usr/local/apisix/conf/debug.yaml:ro \
  --add-host host.docker.internal:host-gateway \
  apache/apisix:3.17.0-debian

# 5. 验证
curl -s http://localhost:9080/healthz
```

## 五、关键配置参考

### APISIX config.yaml（最小 standalone 配置）

```yaml
apisix:
  node_listen: 9080
  enable_ipv6: false

deployment:
  role: data_plane
  role_data_plane:
    config_provider: yaml
```

### APISIX debug.yaml（调试模式）

```yaml
basic:
  enable: true

http_filter:
  enable: true
  enable_header_name: X-APISIX-Dynamic-Debug
#END
```

### PostgREST postgrest.conf

```toml
db-uri = "postgres://authenticator:***@host.docker.internal:6432/app_db?sslmode=disable"
db-schemas = "api_v1_sys,api_v1_sales,api_v1_inventory"
db-anon-role = "web_anon"
server-port = "3000"
```

### Docker Compose APISIX 服务

```yaml
app-apisix:
  image: apache/apisix:3.17.0-debian
  container_name: app-apisix
  restart: unless-stopped
  environment:
    APISIX_STAND_ALONE: "true"
  ports:
    - "9080:9080"
    - "9443:9443"
    - "9180:9180"
  volumes:
    - ./apisix/config.yaml:/usr/local/apisix/conf/config.yaml:ro
    - ./apisix/apisix.yaml:/usr/local/apisix/conf/apisix.yaml:ro
    - ./apisix/debug.yaml:/usr/local/apisix/conf/debug.yaml:ro
  networks:
    - app-net
```

## 七、后续改进方向

1. **apply-src.sh 改用 PGPASSWORD** — 根本解决密码特殊字符问题
2. **Pigsty 释放 80 端口** — 或配置 Nginx 反向代理到 80
