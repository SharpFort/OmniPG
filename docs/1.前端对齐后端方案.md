# OmniAdmin 前端对齐 OmniPG 后端（feature/logto-authn）开发方案

> 生成日期：2026-08-07后端分支：OmniPG `feature/logto-authn`（HEAD 42975f9）前端仓库：OmniAdmin（art-design-pro 3.0.2 + Vue3 + Element Plus + @logto/vue）

## 一、后端现状（API 权威清单）

PostgREST 暴露 `api_v1_public` schema，基址 `http://localhost:3100`（dev）。

### 1.1 视图（GET /api_v1_public/{view}）

| 视图 | 说明 | 关键列 |
| --- | --- | --- |
| users | Logto 用户镜像投影（只读） | id(text), username, email, phone, tenant_id, dept_id, is_active, password_hash(空) |
| role | Logto 角色目录镜像（只读） | id, role_code, role_name, is_active |
| user_role | user_tenants 成员关系投影（只读） | user_id, role_id(=organization_id), tenant_id |
| iam_api | API 权限点目录 | id, api_code, path, method, name, is_active |
| iam_menu | 菜单树 | id, parent_id, menu_name, menu_type, perms, path, component, icon, order_num, is_visible, is_active |
| iam_role_api / iam_role_menu | 角色绑定投影 | role_id, api_id/menu_id |
| department / dict_type / dict_data / position / user_position / login_log | 业务自主表 | 见 §1.3 |
| app_config / config_admin | 系统配置 | config_key, config_value, is_public |
| audit_log / cron_job_log | 审计 / 定时任务日志 | log_type, module, action, result, ip, region... |
| v_user_list | 用户列表（含租户/部门名） | id, username, email, phone, tenant_id, dept_id, tenant_name, dept_name, is_active, organizations(json) |

| v_dept_list | 部门列表（含用户数） | id, dept_name, tenant_name, user_count |
| v_system_stats / v_system_stats_realtime | 系统统计 | total_tenants, active_users, total_users, total_roles... |

| v_user_roles / v_role_users | 用户-角色镜像视图 | user_id, role_code / role_code, user_id |
| v_login_log | 登录日志+地理 | username, login_type, result, ip, region, geo_source |

### 1.2 RPC（POST /rpc/{name}）

**认证 / 用户**

- `ensure_user()` — 登录后 JIT 兜底建档（返回 sub）
- `get_current_user()` — 当前用户信息（含 roles，来自 JWT claims）
- `get_user_permissions()` — 当前用户 API 权限（casbin_rule 视图）
- `get_user_menu()` — 当前用户菜单树（扁平列表 [{id,parent_id,name,path,meta:{title,icon}}]）
- `get_all_public_configs()` / `get_config(key)` — 公开配置

**系统管理（SECURITY DEFINER + has_permission 门槛）**

- `search_users(p_query,p_status,p_dept_id,p_limit,p_offset)` — 用户分页搜索
- `search_audit_log(p_query,p_table_name,p_operation,p_limit,p_offset)` — 审计搜索
- `get_audit_log_timeline(p_start_date,p_end_date)` — 审计时间线
- `get_dept_tree(p_tenant_id uuid)` — 部门树（扁平 + level/path）
- `get_menu_tree_admin()` — 完整菜单树（扁平 + level/sort_order）
- `get_role_permissions(p_role_code text)` — 角色权限详情（apis/menus）
- `update_config(key,value)` — 需 `sys:config:write`
- `rpc_search_login_logs(...)` — 登录日志查询（**⚠️ 权限点 sys:login-log:list 后端未 seed，调用将 42501**）
- `rpc_list_tenants(p_query,p_limit,p_offset)` — 租户列表（`sys:tenant:list`）
- `rpc_list_tenant_members(p_org_id,p_query,p_limit,p_offset)` — 租户成员（`sys:tenant-member:list`）
- `rpc_list_cron_jobs()` / `rpc_list_cron_job_runs(p_limit)` — pg_cron（超管）
- `cleanup_expired_tokens()` — 需 `sys:session:cleanup`

**P1 CRUD（024/025 迁移，均需权限点）**

- 部门：`rpc_create_department` / `rpc_update_department` / `rpc_delete_department`
- 岗位：`rpc_get_position_tree` / `rpc_create_position` / `rpc_update_position` / `rpc_delete_position` / `rpc_assign_user_positions`
- 字典：`rpc_create_dict_type` / `rpc_update_dict_type` / `rpc_delete_dict_type` / `rpc_create_dict_data` / `rpc_update_dict_data` / `rpc_delete_dict_data`
- 菜单：`rpc_create_menu` / `rpc_update_menu` / `rpc_delete_menu`
- 角色绑定：`rpc_set_role_apis(p_role_code, p_api_codes[])` / `rpc_set_role_menus(p_role_code, p_menu_ids[])`
- 用户资料：`rpc_get_user_profile(p_user_id)` / `rpc_update_user_profile(p_user_id, p_updates jsonb)`（本人免权限点）
- 角色镜像：`rpc_sync_user_roles(p_user_id)`（无参=本人 JIT）

### 1.3 表结构要点（migrations 019/022/023/024）

- **Logto 镜像表（只读，webhook 同步）**：`users`（id=nanoid text）、`tenants`、`user_tenants`、`role`、`user_role`（024 新增分配镜像）→ **前端绝不可写这些表**；写路径仅 Logto Console / webhook。
- **PG 自主表（前端可 CRUD）**：`department`、`position`、`user_position`、`dict_type`、`dict_data`、`iam_menu`、`iam_api`、`iam_role_api`、`iam_role_menu`、`app_config`、`user_profile`
- `iam_menu` 新列：menu_type(directory/menu/button)、perms、component、is_visible（022）
- `audit_log` 扩展：log_type/module/action/target_type/target_id/result/ip/user_agent/region/duration_ms（019）
- `sys_user_profile` → `user_profile`（user_id text）
- RLS：镜像表租户隔离 + 超管例外；业务表租户隔离；写路径经 SECURITY DEFINER RPC

### 1.4 已知后端问题（前端需容错/标注）

1. `get_online_users` 引用不存在的 `v_online_users` → 调用必报错。**前端不接此 RPC**（在线用户页面移除）。
2. `rpc_search_login_logs` 权限点 `sys:login-log:list` 未 seed → 即使超管也 42501。**登录日志页显示"无权限"提示**（待后端补 seed）。
3. `role` 镜像表缺 `role_super_admin`（webhook 未同步，Logto 端存在）→ 角色列表不显示超管角色。**前端角色页标注"角色目录来自 Logto，缺同步时以 Console 为准"**。
4. `is_super_admin()` 只认 roles 中 `super_admin`/`admin`，不认 `role_super_admin` → RLS 全量读受影响；但视图为 owner 权限 + RPC 走 has_permission（role_super_admin 已绑全部权限点）→ 功能不受阻。
5. 菜单种子数据 menu_type 全部为 'menu'（按钮项 UserAdd 等也是 menu），component 为空 → 前端用 path 映射组件。

## 二、前端改造方案

### 2.1 认证流程（Logto）

| 页面 | 现状 | 改造 |
| --- | --- | --- |
| 登录 /auth/login | 已有"统一身份认证登录"按钮 | 增加"注册账号"入口（跳注册页）；保留 Logto signIn |
| 注册 /auth/register | 假注册（模拟 setTimeout） | 改为 Logto 注册：`logtoClient.signIn(redirectUri, { interactionMode: 'signUp' })`（Logto SDK 支持 signUp 交互模式），注册成功后由 Logto 回调完成建档 |
| 回调 /auth/callback | 已实现 handleSignInCallback + ensure_user + get_current_user | 基本保留；跳转改为 `router.replace(redirect)`；补充错误兜底 |
| 忘记密码 /auth/forget-password | 空壳 | 提示"请联系管理员重置密码"（Logto 无自助找回，走 Console） |
| 登出 | userStore.logOut 未调 Logto signOut | 修正：`logtoClient.signOut(postLogoutRedirectUri)` 后再清本地 |

### 2.2 API 层重写（src/api/）

**auth.ts**

- `fetchLogout` 删除（后端无 logout RPC）→ 改由 config/logto.ts signOut 处理
- `fetchGetUserPermissions` 返回类型修正（{user_id, roles, permissions}）

**system-manage.ts（全面重写，对齐 §1.2）**

- 删除：create_user / update_user_status / assign_role_to_user / batch_assign_roles / get_user_roles / update_role_permissions / get_role_users / force_logout_user / reset_user_password / get_user_sessions（后端均不存在，属 Casdoor 残留）
- 修正：`fetchGetRolePermissions` 参数 p_role_id → **p_role_code**
- 新增：部门/岗位/字典/菜单 CRUD、set_role_apis/menus、get_user_profile/update_user_profile、sync_user_roles、list_tenants/list_tenant_members、search_login_logs、get_position_tree

**新增 api 模块**

- `audit.ts`：search_audit_log / get_audit_log_timeline / v_audit_log_detail 查询
- `monitor.ts`：v_system_stats / v_system_stats_realtime / rpc_list_cron_jobs / rpc_list_cron_job_runs
- `dict.ts`：dict_type/dict_data 视图 + CRUD RPC（或并入 system-manage）
- `tenant.ts`：rpc_list_tenants / rpc_list_tenant_members（或并入 system-manage）

### 2.3 类型定义（src/types/api/api.d.ts）

- `UserInfo`：增加 tenant_name/dept_name、roles 为 string[]
- `UserListItem`：roles → organizations(json 数组)；增加 user_role 列来源
- `MenuTreeItem`：对齐 iam_menu 新列（menu_type/perms/component/is_visible/order_num）
- 新增：Dept/Position/Dict/Tenant/LoginLog/AuditLog/CronJob 类型

### 2.4 菜单与路由

- **后端菜单适配**（MenuProcessor.processBackendMenu）：
  - 扁平列表 → 树（parent_id）
  - path → component 映射表（user→/system/user、role→/system/role、menu→/system/menu、api→/system/api、dept→/system/dept、position→/system/position、dict→/system/dict、tenant→/system/tenant、login-log→/system/login-log、audit-log→/system/audit-log、monitor→/system/monitor）
  - menu_type=button 过滤（按钮不注册路由）
  - 树为空时 fallback 到本地 asyncRoutes
- **本地 asyncRoutes**（router/modules/*）：
  - 更新 system.ts roles：`['R_SUPER','R_ADMIN']` → `['role_super_admin','tenant_admin']`
  - 新增子路由：dept、position、dict、tenant、login-log、audit-log、monitor
- **VITE_ACCESS_MODE**：保持 `frontend`（本地路由全量、角色过滤），后端菜单适配逻辑保留以备切换

### 2.5 页面开发（src/views/system/）

| 页面 | 数据源 | 操作 |
| --- | --- | --- |
| user 用户管理 | v_user_list + search_users | 搜索/分页/编辑资料(user_profile)/查看角色(v_user_roles)。删除/禁用→Logto 侧，提示 |
| role 角色管理 | v_role_list | 权限分配（get_role_permissions + set_role_apis/menus）、成员(v_role_users)。新增/删除→Logto Console，提示 |
| menu 菜单管理 | get_menu_tree_admin | 树形表格 + rpc_create/update/delete_menu（含 menu_type/perms/component 字段） |
| api API 管理 | iam_api 视图 | 列表（api_code/path/method） |
| dept 部门管理（新） | get_dept_tree | 树形 + rpc_create/update/delete_department |
| position 岗位管理（新） | rpc_get_position_tree | 树形 + CRUD + 分配 |
| dict 字典管理（新） | v_dict_list / dict_data | 类型 + 数据项两级 CRUD |
| tenant 租户管理（新） | rpc_list_tenants / rpc_list_tenant_members | 租户列表 + 成员查看 |
| login-log 登录日志（新） | rpc_search_login_logs | 列表 + 筛选；无权限时降级提示 |
| audit-log 审计日志（新） | search_audit_log + v_audit_log_detail | 列表 + 关键词/表名/操作筛选 |
| monitor 系统监控（新） | v_system_stats + cron RPC | 统计卡片 + pg_cron 任务/运行历史 |
| user-center 个人中心 | rpc_get_user_profile / update_user_profile | 资料编辑（本人免权限点） |
| dashboard 仪表盘 | v_system_stats | 统计卡片数据修正 |

### 2.6 权限指令

- `v-auth` 指令当前基于路由 meta.authList（前端模式）→ 保留
- 新增 `usePermission` composable：`hasPerm(code)` 判断当前用户是否具备权限点
  - 超管角色（role_super_admin/admin/super_admin）短路 true
  - 否则拉取 v_role_api_detail（role_code ∈ roles）的 api_code 集合
- 页面按钮用 `v-perm="'sys:dept:create'"` 指令控制

   - 检查各页面数据加载（用户/角色/菜单/部门/字典/租户/审计/监控）
   - 注册流程（若可行）
4. 提交推送 GitHub

## 三、执行顺序

1. 类型定义 → 2. API 层 → 3. 认证页（注册/忘记密码/登出） → 4. 路由/菜单 → 5. 系统管理页面 → 6. 仪表盘/个人中心 → 7. lint+build → 8. 浏览器验证 → 9. 提交推送

## 四、风险与说明

- 登录日志页将因后端缺权限点 seed 而显示无权限——前端做降级提示，后端补 seed 后即恢复（一行 SQL，已记录）。
- 角色/用户的新增、删除、改状态、重置密码等写操作在 Logto 侧（OSS Console），前端不重复造轮子，页面内做引导提示。
- 测试账号 testC（role_super_admin，全局超管，无组织）可访问全部管理页面。
